# 合并冲突编辑器验证

冲突阅读器保留原有版本查看能力。进入独立编辑器后可对照 Base、stage 2、stage 3 和工作区结果，逐块采用任意一方、依次保留两方，或直接编辑结果。保存创建文件备份，只替换工作区文件。标记已解决需要独立操作，再通过已有入口完成或中止合并。

保存核对仓库、revision、各 stage 的对象 ID 和模式，以及工作区原始字节的 SHA-256。发现外部改动时提示重新读取。撤销检查保存后字节与原冲突 stage，后续编辑发生变化时保留现有文件。编辑器支持普通 UTF-8 文本，保留 BOM 和一致的 LF 或 CRLF。缺失的 stage 会明确显示，二进制、混合换行及超出读取预算的内容走只读查看。

- Rust 用真实 Git 仓库验证 modify/modify、add/add、modify/delete，从读取 stage 到保存、显式标记和创建两个父提交的 merge commit。另核对 BOM、CRLF、无末尾换行、剩余冲突标记、旧 stage、外部改动和备份撤销。
- 前端用例覆盖部分保存、分开标记、Tab 循环、中止合并和切换项目时清理编辑器，以及丢弃迟到的读取结果。
- Rust 测试使用 Windows PowerShell 和 MSVC。前端用例运行在 jsdom，覆盖 DOM 键盘和状态交互。真实 Windows 窗口焦点与 macOS 均未验证。
