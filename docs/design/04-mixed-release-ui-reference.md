图内可切换“日常查看、提交任务、分支与同步、合并冲突、Stash”五个场景及深浅色。它重点回答常驻元素与任务展开位置；丢弃确认、pull 策略、push 预览等对话框采用文字入口示意，完整写操作流程仍以 V2 规格为准。

## 相对旧图的改动

1. 三枚常驻同步按钮收为一个“同步”入口，当前分支和收发计数持续可见。
2. 固定在文件区底部的提交表单改为可收起底部“提交”页；左侧文件列表不因日常阅读而被压缩。
3. 块操作从代码文本上方移到 hunk 标题行，并使用完整动作文字；中央连接带保持纯阅读语义。
4. 底部 Git 区统一容纳日志、提交、Stash 和操作输出，主 diff 阅读器保持同一个。
5. 分支切换和同步的风险动作显示目标与后果；冲突继续只读查看，标记解决在文件列表操作。

## 已确认的布局方向

- 提交表单停靠底部“提交”页，日常阅读时可收起。
- 标题栏以一个“同步”入口展开获取、拉取与推送，持续显示当前分支与收发计数。
- hunk 操作放在块标题行，并使用完整动作文字。

以上布局方向按图作为后续实现参考。交互参考不替代 V1/V2 产品规格、写操作安全要求或真实数据验收。原 [二期增量 UI 提案](03-phase2-ui-proposal.md)保留作历史对照；此次确认只解除 V2-02 的 UI 效果图确认前置条件，不表示任务已开工。
