# Oris V2 产品规格

状态：二期规划基线（2026-09-23），尚未实施。决策依据见 [V2 决策登记](../decisions/v2-decisions.md)。V1 规格中的需求组（R-PROJECT、R-DIFF 等）继续有效；本文只描述二期新增与修订的内容。

## 1. 定位与主路径

二期在“看懂变化”之上，补充“把变化交出去”所需的最少操作，同时让各类切换更快。首要体验仍是易读的 diff，**不以覆盖更多 Git 命令为目标**；低频操作、或需要一整套专属界面的操作，继续交给命令行。

新增主路径：
- 提交路径：查看本地变化 → 暂存文件或 hunk → 填写提交信息 → 提交 → 推送。
- 同步路径：获取远端 → 拉取（仅快进或合并）→ 如有冲突，只读查看 → 在外部工具中解决 → 回到 Oris 标记已解决 → 完成合并提交。
- 切换路径：stash 当前改动 → 切换或新建分支 → 工作 → 切回 → 恢复 stash。

V1 已确认的平台、Git 最低版本、只读浏览边界都保持不变。写操作只在用户主动点击时发生。

## 2. 需求

### R-STAGE：暂存

- 未暂存范围内的文件可以暂存，已暂存范围内的文件可以取消暂存；支持多选批量操作。新增、删除、rename、未跟踪文件都能正确暂存。
- 冲突文件暂存即“标记已解决”（见 R-MERGE），操作文案需要与普通暂存区分。
- hunk 级（任务 V2-05）：在 diff 阅读器中逐个 hunk 暂存或取消暂存。只在“未暂存”“已暂存”两个范围内可用；“全部”范围、忽略空白模式、冲突、二进制、子模块、仅 mode 变化时禁用，并说明原因。
- 空 HEAD（首次提交前）也能取消暂存。
- 操作结果要可观察：文件在两个范围之间移动，统计同步更新。失败时恢复原显示并给出 Git 的错误摘要。

### R-DISCARD：丢弃本地改动

- 未暂存范围：把工作区文件恢复到 index 版本；未跟踪文件为删除。“全部”范围：把 index 和工作区都恢复到 HEAD。已暂存范围不提供丢弃，只提供取消暂存。
- 丢弃必须二次确认，确认框列出受影响的文件数，以及是否包含未跟踪文件。
- 安全网：丢弃前备份被丢弃的工作区内容与暂存内容，提供“撤销丢弃”。撤销时如果目标文件在丢弃之后又被修改，需再次确认覆盖。单文件超出备份预算时不备份，确认框明确标注“不可撤销”。备份记录有数量上限，写入应用数据目录，不写入仓库工作区。
- 子模块条目（gitlink）不提供丢弃，并说明原因。
- hunk 级丢弃（任务 V2-05）只在未暂存范围可用，同样纳入安全网。

### R-COMMIT：提交

- 提交面板：提交信息输入框（首行摘要 + 正文），显示已暂存文件数；每个项目保存一份未完成的提交信息草稿，切换项目或重启后恢复。
- 只提交已暂存内容。没有已暂存内容时，提交按钮不可用并提示原因。
- 提交并推送（V2-D37，取代 amend）：勾选后提交成功即推送当前分支；已有上游直接推送，没有上游时打开推送预览选择 remote；分离 HEAD 时不可用。推送规则同 R-SYNC 的推送。
- 撤销最近提交：HEAD 回退一个提交，改动回到暂存区，工作区不变。HEAD 是合并提交时说明会回到第一个父提交；根提交时仓库回到无提交状态。
- 已推送保护：HEAD 已包含在上游分支中时，撤销不可用，并说明需要在命令行处理（因为二期不支持 force push）。无上游时不做此限制。
- hooks（pre-commit、commit-msg 等）按用户仓库配置执行；执行中显示进度，可以取消；失败时展示 hook 输出，不提供跳过 hooks 的选项。签名等按用户 git config 执行。
- 提交成功后清空草稿，文件列表、分支状态、领先计数刷新。

### R-STASH：储藏

- stash 当前改动：可填写说明，可选择是否包含未跟踪文件，也可以只 stash 选中的文件。
- stash 列表：说明、时间、所在分支。可以查看 stash 的内容（复用 diff 阅读器；包含未跟踪部分时单独列出）。
- apply / pop / drop。drop 需要确认。操作前核对目标 stash 的身份，列表在外部被修改时拒绝执行并刷新列表。
- apply 或 pop 出现冲突时，stash 保留在列表中，进入只读冲突查看；在外部解决后，用户自行决定是否 drop。

### R-BRANCHOP：分支与检出

- 新建分支：可以从当前 HEAD、选中的分支或提交创建，可选择创建后是否立即切换。分支名在提交前用 Git 规则校验。
- 切换到本地分支；切换到远端分支时创建同名本地跟踪分支（已存在同名本地分支时提示并让用户选择）。
- 检出指定提交（从提交历史进入），进入 detached HEAD；界面持续提示当前处于 detached 状态，并提供“从这里新建分支”。
- 工作区有改动导致 Git 拒绝切换时，展示原因并提供“stash 后切换”。切换完成后不自动恢复 stash，而是提示可以恢复。
- 重命名本地分支；删除本地分支（不能删除当前分支）。分支未合并时二次确认，说明其中的提交之后只能通过 reflog 找回。
- 为当前分支设置或更换上游。
- 不支持：删除或重命名远端分支、remote 增删。

### R-SYNC：远端同步

- fetch 沿用 V1 R-REMOTE 的全部约束。
- pull：拉取当前分支的上游。提供“仅快进”（默认）和“合并”两种方式，始终不走 rebase；如果用户配置了 `pull.rebase=true`，界面要说明 Oris 会以合并方式执行。“仅快进”因分叉失败时，说明原因并提供改用“合并”。工作区改动阻止拉取时，提供“stash 后拉取”。无上游时不可用，并引导设置上游。
- push：推送当前分支。没有上游时，选择 remote（只有一个时默认选中），推送并设置上游。被拒绝（远端有新提交）时提示先拉取，不提供强制推送。二期不推送 tag。
- pull、push、fetch 都显示进度，可以取消。取消或失败后重新读取实际 refs，并如实报告，不承诺回滚。
- 认证使用用户已有的凭据设施；认证失败或长时间无响应时终止，并给出可以采取的措施。
- 工具栏常驻显示当前分支相对上游的领先/落后数，数据来源与新鲜度遵循 V1 R-BRANCH。

### R-MERGE：合并与进行中状态

- 把选中的本地或远端跟踪分支合并到当前分支；默认遵循用户的 `merge.ff` 配置，可以选择“总是创建合并提交”。
- 出现冲突时进入“合并进行中”状态：diff 区上方常驻横幅，显示冲突文件数，提供“查看冲突”“中止合并”；冲突全部标记已解决后，提供“完成合并”（可编辑默认合并信息）。
- 标记已解决：暂存冲突文件。如果文件中仍有冲突标记（`<<<<<<<` 等），先警告，再允许用户确认。
- 冲突查看复用 V1 任务 03 的只读冲突阅读（Base / stage 2 / stage 3 / 工作区）。
- 仓库处于 Oris 不支持的进行中状态（外部发起的 rebase、cherry-pick、revert、bisect）时，横幅显示状态，并禁用所有写操作（刷新和阅读不受影响），提示回到命令行完成或中止。

### R-OPSAFE：写操作的通用约束

- 写操作只能由用户显式点击或确认触发。浏览、刷新、切换项目、应用启动、快照恢复都不触发写操作（V2-D09 的 stat 缓存回写除外，且仅在限定时机进行）。
- 同一仓库一次只执行一个写操作，执行期间其他写入口不可用；阅读仍然可用。
- 确认分级：可以直接撤销的（stage、unstage）不确认；会改变工作区或历史的（discard、撤销提交、删除分支、drop stash、中止合并）需要确认；不可撤销的在确认框中明确标注。
- 所有写操作都有明确的结束状态（成功 / 失败 / 已取消）。失败时展示 Git 输出摘要，**不自动重试**。
- 外部工具同时在操作仓库（例如 `index.lock` 已存在）时，说明原因并停止。
- 基于未完成校验的快照（V2-D08）时，所有写入口不可用。
- 写操作完成后只刷新受影响的部分，不重建整个视图，也不丢失当前阅读位置。

### R-FLOW：流畅度

以下场景都要按[验收计划](../validation/v2-acceptance.md)的预算实测，与 V1 基线对比。

- 首次打开项目：先出文件列表，再补统计、分支等次要信息；第一个文件的 diff 紧接着加载。
- 再次打开（重启应用）：立即显示上次快照，标明“校验中”；校验后只替换有差异的部分，不闪烁、不重置阅读位置。
- 切换项目：立即显示该项目上次的状态；项目在后台期间有变化时，切回后再刷新并标明刷新中。
- 切换文件：已读过或相邻的文件立即显示；连续快速切换（按住方向键）时只加载最终停留的文件，中间结果不落屏。
- 切换显示区域（未暂存 / 已暂存 / 全部）：不需要重新扫描仓库即可立即显示。
- Git 操作之后：暂存、取消暂存立即在界面上生效（失败时回滚）；其他操作结束后只刷新受影响的部分。
- 外部变化：构建工具等大量写文件时不出现界面卡顿或事件风暴；被 gitignore 的路径不触发刷新。

### R-MEM：资源占用

- 常驻资源都有上限：内容缓存、后台 Git 进程、文件监听、快照持久化。长时间使用后内存不持续增长。
- 打开的项目数量增加时，常驻内存不能线性增长；后台项目只保留轻量状态。

### R-SETTINGS：设置（任务 V2-06）

- 入口：标题栏右侧的“设置”按钮（取代现有的浅 / 深色切换按钮），快捷键 Windows 为 Ctrl+,，macOS 为 Cmd+,。
- 形式：设置窗口，左侧为分类列表，右侧为当前分类的设置项。修改即时生效并自动保存，不设“应用 / 确定”按钮；关闭窗口不丢失已做的修改。
- 分类：本期实现“外观”与“Git”两个分类。分类结构要允许以后增加新分类（例如 Diff 阅读、通用），而不需要改动设置框架。
- 迁移：路径栏的“Git 设置”、diff 工具栏的字号滑块、标题栏的浅 / 深色按钮全部移除，功能移入设置；已有的取值在首次启动新版本时迁移过去。
- 持久化：写入应用数据目录，带版本号；文件损坏时回退为默认值并提示，不影响项目列表。
- Git 分类：Git 可执行文件路径（留空为自动发现），显示当前实际使用的路径、版本与最低版本要求。修改后立即校验；路径无效或版本不支持时提示原因，并继续使用原来的有效设置。设置为全局生效（V2-D24）。

### R-APPEARANCE：外观（任务 V2-06）

- 主题模式：浅色 / 深色 / 跟随系统。跟随系统时，系统切换浅深色后 Oris 实时跟随。
- 配色方案：浅色、深色各选一套方案（与 VS Code 的“首选浅色 / 首选深色主题”模型相同），主题模式决定当前使用哪一套。高对比方案归入对应的浅色或深色列表，并标注“高对比”。
- 方案来源：VS Code 内置配色方案的移植，19 套全部移植（V2-D31），另保留当前的 Oris 配色并作为默认（V2-D32）。列表中每个方案显示小色板预览。
- 配色覆盖整个应用：标题栏、项目栏、侧栏、文件状态、diff 阅读器（背景、行号、语法高亮、选中、搜索命中）、图片阅读器背景、对话框、横幅、状态栏。
- diff 颜色语义：沿用 Oris 已确认的“修改蓝、新增绿、删除灰”，色值从方案中取；不提供红绿切换（V2-D30）。
- 字号：diff 阅读器字号，范围 11–18（沿用现有范围）；保留 Ctrl / Cmd + `=` / `-` / `0` 快捷调整，并与设置保持同步（V2-D25）。
- 切换主题模式、配色方案、字号都即时生效，不重建 diff 阅读器，不丢失阅读位置、选区、滚动位置和搜索状态。
- 启动时直接以保存的配色显示界面，不出现先显示默认配色再切换的闪烁。
- 在所有方案下，文件状态字母、图例和其他非颜色辅助标识都保持可辨认；高对比方案使用描边区分界面元素。

## 3. 界面落点（以已确认的[一二期混合发布参考图](../design/04-mixed-release-ui-reference.md)为视觉参考）

- 左侧文件区：保留未暂存 / 已暂存 / 全部比较范围；文件行提供暂存、取消暂存和适用范围内的丢弃入口，另有右键菜单；复选框只选择批量操作目标，不自动暂存。
- 标题栏：当前分支与领先/落后数持续可见；点击分支打开搜索、本地/远端分组和分支操作弹层；单一“同步”入口展开 fetch、pull、push，拉取策略和推送目标在后续确认界面呈现。
- 底部 Git 区（含 V1 任务 04 的日志）：提供可收起的日志 / 提交 / Stash / 操作输出页签。选择“提交”才展开提交草稿、“提交并推送”勾选与提交按钮；日志中的提交右键菜单加入“检出”“从这里新建分支”“合并到当前分支”。
- diff 区上方：进行中状态横幅、detached HEAD 提示、快照“校验中”提示。
- diff 的 hunk 标题行：使用文字按钮执行适用范围内的暂存 / 取消暂存 / 丢弃（任务 V2-05）；中央连接区不出现写入箭头。
- 状态栏：写操作的进度与结果，点击展开最近一次操作的 Git 输出。
- 设置入口（任务 V2-06）：标题栏右侧“设置”按钮取代参考图中的浅 / 深色按钮；路径栏不再有“Git 设置”，diff 工具栏不再有字号滑块。设置窗口布局见已确认的[设置窗口效果图](../design/05-settings-ui.md)。

## 4. 明确不支持

自定义单个颜色、导入外部 VS Code 主题或扩展、图标主题、界面字体选择（以上为 V2-06 的排除项）；rebase（任何形式）、force push、冲突解决编辑器、行级 stage、tag、cherry-pick、revert、reset 到指定提交、删除或重命名远端分支、remote 管理、submodule / worktree / LFS / sparse-checkout 操作、`git clean`、bisect、blame、reflog 界面、patch 导入导出、hooks 管理、签名配置界面、clone / init、PR / Issue、终端。V1 已排除的内容继续排除。

不构建自动重试、后台自动 fetch、操作队列或恢复作业系统。

## 5. 完成标准

六项二期任务全部通过验收；R-FLOW 各场景在两个平台都达到预先固定的预算，并与 V1 基线有对比记录；写操作的安全用例（确认、取消、并发、外部锁、不支持的进行中状态）都有证据；未验证项明确列出，不得称二期已交付。一二期合并为一次发布（V2-D19），发布验收由 V1 任务 06 统一执行。
