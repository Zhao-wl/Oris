## 本阶段修复的缺陷与权限收紧

| # | 现象 | 原因与修复 | 提交 |
| --- | --- | --- | --- |
| 1 | 取消 AI 命令行工具或超时后，工具启动的子进程仍在运行 | 只结束了直接子进程；改为用 `ProcessTree`（Windows Job Object）启动并在取消 / 超时时结束整棵进程树。新增后端用例：假 `codex.cmd` 启动一个孙进程，取消后孙进程仍在（修复前失败）；同一用例核对工具在临时目录运行、带只读沙箱参数 | `8ea1183` |
| 2 | npm 安装的 `claude.cmd` 无法启动（“无法启动 AI 工具”） | Rust 标准库拒绝向 `.cmd` / `.bat` 传含换行的参数，而系统提示词是多行文本；对批处理包装的工具把系统提示词中的换行换成空格。界面验收用假 `claude.cmd` 发现，新增后端用例 | `ae7254d` |
| 3 | AI 执行的前置检查失败（例如外部持有 `index.lock`）时只显示“执行失败”，没有原因 | 显示操作的具体原因（与普通入口相同的文字） | `ae7254d` |
| 4 | AI 计划可以修改 Git 可执行文件路径（之后 Oris 会运行该路径，等于把任意程序执行交给模型） | 按用户决定（V2-D67）从 AI 可改的设置中移除，计划中出现时拦下并说明到“设置 → Git”手动修改；规划上下文不再包含 Git 路径设置 | `8ea1183` |
| 5 | AI 执行丢弃 / 撤销丢弃 / 标记已解决时会带上模型给出的确认标志（例如超过备份预算的不可撤销丢弃） | 按用户决定（V2-D68）一律不带确认标志；后端要求确认时停止并说明，由用户用普通入口处理 | `8ea1183` |
