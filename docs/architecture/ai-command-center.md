# Oris AI 操作中心方案

状态：统一入口与现有类型化操作已接入；更细粒度的 SOP、只读审查和多步计划仍是后续方案。基于 2026-09-25 的 Oris 工作树。用户已明确：`@xxx` 的主要作用是按需注入提示词与 SOP，提高 AI 判断的稳定性；它不是必须使用的命令，也不直接触发执行。`@设置` 与 `@Git` 是合适的示例，拉取使用 `@拉取`。

当前实现：标题栏的 AI 按钮与 Windows `Ctrl+P` / macOS `⌘P` 打开统一输入框；现有 `OperationRequest`、项目及阅读界面动作、外观/Git/AI 快捷键与配置切换已接入白名单。模型返回有效计划后立即执行，不再显示二次确认；描述驱动提交继续使用专用整文件选择流程。输入独立的 `@` 标签时显示候选，`@Git`、`@设置`、`@提交`、`@拉取`、`@合并` 加载可在设置中修改的提示词；仅识别位于开头或空格之后、且后面为空格或结尾的完整标签。更多动作的上下文、细粒度 SOP、只读审查和多步执行仍需后续实现。

AI 指令统一由模型规划，不按特定中文措辞在前端直接选择动作。对暂存和取消暂存，模型可返回具体文件 ID，或返回 `pathIds: "all"`；后者由 Oris 根据当前快照展开为对应范围的全部文件，执行前仍检查仓库 revision。规划上下文中的文件列表只传未暂存和已暂存两份，避免重复传送合并后的 `all` 列表。

下文第 3 至 7 节描述完整目标架构，其中自动识别后再次加载 SOP、逐能力预检令牌和多步执行尚未实现。

## 1. 目标与边界

将标题栏右侧的“提交 · N”改为“✦ AI”，打开统一输入框。它始终可用；未打开项目时只开放不依赖仓库的设置与帮助。现有的 AI 提交功能成为 Git 领域内的一个 SOP，不再决定整个入口的名称。用户可输入 `@Git 提交登录页相关文件`、`@设置 把字号调大一点`，也可直接输入自然语言。`@Git` 注入 Git 领域的术语、约束、SOP 索引和可用接口说明；`@设置` 注入设置领域的相应内容；`@提交` 可进一步注入提交专用 SOP。它们帮助模型理解任务，不构成执行授权。

AI 负责理解意图、选择候选对象、生成建议和解释；Oris 负责读取可信状态、校验参数、执行固定操作并核对结果。用户发送 AI 指令后不再二次确认；对象不明确或校验不通过时停止并说明原因。任何 Git 写入仍使用 `OperationRunner`，任何界面设置仍使用 `SettingsStore`。不向模型提供任意 shell、Git 参数、文件写入或 Tauri IPC 调用能力。

统一入口不取代现有 Git 按钮和设置界面；AI 的计划应可跳转到对应的原生界面，用户也能继续手动操作。

## 2. 功能清单与实施顺序

| 提示词包与示例 | 产出 | 当前基础 | 执行规则 |
| --- | --- | --- | --- |
| `@提交` “提交登录页相关文件” | 文件选择、提交信息 | `commitSelected`、AI 提交已存在 | 复用现有文件级提交；选择明确时直接执行 |
| `@解释` “这次改动做了什么” | 改动摘要、风险和引用文件 | Diff 与历史读取已存在 | 只读，回答可定位到文件与行 |
| `@审查` “提交前检查” | 可操作问题清单 | Diff 已存在 | 只读；不得把未运行的测试说成已通过 |
| `@暂存` / `@取消暂存` | 文件列表和影响范围 | `stage` / `unstage` 已存在 | 按 `pathId`，复核 revision 后执行 |
| `@切换分支` “切到 feature/x” | 目标分支和工作区影响 | `branchSwitch` 等已存在 | 目标需解析为唯一完整 ref；工作区阻塞时按原生流程询问 stash |
| `@获取` / `@推送` | 远端和范围 | `fetch` / `push` 已存在 | 推送必须明确 remote、分支；失败不自动重试 |
| `@拉取` “拉取当前分支” | 注入拉取 SOP，识别当前分支与上游 | `pull` 已存在 | 无上游时询问目标；分叉、工作区阻塞时由 Oris 校验，不能直接执行则报错 |
| `@合并` “把 feature/x 合入当前分支” | 源、目标、OID、合并方式与冲突风险 | `merge` / `mergeAbort` / `mergeCommit` 已存在 | 对目标 ref 和 OID 做执行前复核；不自动隐藏 stash 或强制覆盖 |
| `@设置` “换深色主题 / 放大字号” | 可见的外观变化 | `themeMode` / `fontSize` 已存在 | 即时执行，可撤销；`@主题` / `@字号` 可作为更具体的提示词包 |
| `@储藏` / `@恢复储藏` | stash 内容和应用范围 | stash 操作已存在 | 目标明确时直接执行；状态不一致则停止 |
| `@撤销提交` | 最近提交信息 | `undoCommit` 已存在 | 只支持当前后端允许的未推送提交，核对 `expectedHead` |
| `@回滚` | 先澄清目标与方法 | 部分能力已存在 | 不设单一默认动作；区分撤销提交、撤销丢弃、丢弃工作区、revert 与 reset |
| `@解决冲突` | 冲突分析与候选补丁 | 目前主要为只读冲突查看和标记已解决 | 后续新增受限补丁接口和逐块预览；现阶段只分析，不自动改文件或标记已解决 |

后续可加入 `@比较`（两分支或两提交差异）、`@定位`（找改动或历史）、`@生成发布说明`（只读文本）、`@新建分支`、`@重命名分支`、`@设置上游`。高风险能力如强制推送、硬重置、清理未跟踪文件、自动解决全部冲突暂不开放给 AI 执行。

## 3. 输入与交互

1. 标题栏显示“✦ AI”，旁边可保留未提交文件数徽标；原 AI 快捷键改为打开统一输入框。输入框一行起步，按内容增高，输入 `@` 弹出可搜索的提示词包菜单，展示 `@Git`、`@设置` 和更具体的 `@提交` 等包的作用与可用状态。已选包以可移除标签展示，用户可同时选领域包和具体 SOP 包。
2. 本地解析器只识别 `@` 标签并注入对应内容，不把标签直接映射成操作。无标签时，先用轻量上下文让模型判断意图，再自动加载可能相关的 SOP；有标签时仍由模型结合用户描述提出意图和计划。Oris 将所加载的 SOP、识别出的操作和依据显示给用户，并允许改选。标签与描述冲突、多个意图或对象不唯一时先询问，不执行猜测动作。
3. 处理区分“读取上下文 → 生成计划 → 执行中 → 核对结果”。输入框内显示旋转进度；计划有效时直接执行。对象不明确时返回澄清问题。
4. 关闭输入框时取消尚在进行的 AI 识别和计划生成。Git 操作已经开始时，关闭输入框只收起视图；状态栏继续展示进度和已有的取消入口，不能把关闭窗口当作操作已中断。
5. 输入框不提供“直接提交”开关。发送 AI 指令即请求执行；提交文件选择无歧义时直接执行，其他写操作通过 Oris 原有校验后直接执行。

## 4. SOP 与能力注册表

每个 SOP 是版本化的能力声明，不是只靠一段自由文本提示词。`@xxx` 只控制要注入哪些提示词包与 SOP 内容；内置 SOP 可以有用户可编辑的提示词扩展，但必需参数、校验和执行边界由 Oris 固定。

```ts
interface AiPromptPack {
  id: string;                         // git, settings, git.commit ...
  tag: string;                        // @Git、@设置、@提交 ...
  version: number;
  instructions: string;               // 该领域/操作的术语、决策步骤和输出偏好
  capabilityIds: string[];            // 可参考的 SOP；并非执行授权
  contextNeeds: string[];             // 注入前最少读取哪些事实
}

interface AiCapability {
  id: string;                         // commit.selected, git.merge, appearance.fontSize ...
  domain: "git" | "settings" | "read";
  promptTags: string[];               // @Git、@提交 等；仅用于注入提示词
  version: number;
  availability: "ready" | "readOnly" | "planned";
  inputSchema: unknown;               // 结构化参数与必填项
  contextNeeds: string[];             // snapshot, changes, refs, diff ...
  outputSchema: unknown;              // AI 只返回计划，不返回命令行
  previewKind: string;
  risk: "read" | "reversible" | "write" | "destructive";
  executor?: string;                  // Oris 内置操作 ID，非任意函数名
  promptKey: string;                  // 用户可编辑的本操作提示词
}
```

模型只返回意图与计划，例如 `{ capabilityId: "commit.selected", arguments: { pathIds: ["..."], message: "..." }, questions: [] }`；返回值须通过对应 `outputSchema` 和 Oris 的状态校验。找不到唯一能力或必需参数时，返回 `questions` 而非臆造参数。多个提示词包可以叠加，冲突时以 Oris 固定规则和用户本次明确描述为准，不让提示词包提升操作权限。

SOP 的目标流程：**读取快照 → 收集最小上下文 → 生成结构化计划 → 校验参数 → 调用受限接口 → 重新读取并报告实际状态**。计划须绑定仓库和快照版本；涉及 HEAD、分支或远端时还要带期望 OID。过期计划拒绝执行，要求重新输入。

例如 `@合并` 的计划只含 `targetRef`、`expectedTargetOid`、`noFf`、当前分支与预期 HEAD；Oris 在执行前再次校验完整 ref、OID、仓库状态和工作区，并映射到现有 `{ kind: "merge", target, expected, noFf }`。模型不能提供原始 Git 参数。

## 5. 给 AI 的标准接口

接口按最小权限分层，所有参数和响应使用带版本的结构化 JSON：

- **只读上下文**：`getRepositoryContext(repoId)`、`listChanges(repoId, scope)`、`readDiff(repoId, pathIds, budget)`、`listRefs(repoId)`、`readHistory(repoId, limit)`、`getPreferences()`。只返回当前 SOP 必需的数据，文本、文件数与 token 数均设上限；二进制内容只给元数据。
- **计划与预检**：`validatePlan(capabilityId, plan, expectedRevision)`。校验路径 ID、完整 ref、OID、消息长度、当前写锁与进行中状态；执行依据由 Oris 核验，不依赖模型自述。
- **执行**：`executeValidatedPlan(planToken)`。短时有效的 token 绑定预检结果、仓库、参数与 revision；执行时再核验，最终只调 `OperationRunner` 或设置 store 的白名单方法。
- **反馈**：`getOperationStatus(opId)`、`cancelOperation(opId)`、`readOutcome(opId)`。AI 的“成功”必须来自实际执行结果及刷新后的快照。

AI 只能看见能力清单与被授权的只读上下文。模型输出中的工具名、路径或命令不直接执行。仓库文件、提交信息和 Diff 属于不可信输入，不能改变 SOP 的执行权限。

按需注入的效率策略：第一步只提供少量提示词包的名称与用途；用户写 `@Git` / `@设置` 时注入该领域的规则和 SOP 索引，写 `@提交` 时再注入提交专用 SOP；没有标签时先识别意图，再自动选择需要的包。确定具体计划后才读取所需仓库状态与完整 SOP。处理外观设置不读取 Diff；上下文按需缓存并用 revision 失效。多个标签合并时按“通用规则 → 领域 → 具体 SOP → 用户输入”的顺序组装，重复规则去重，明确标记各段来源与版本。

## 6. 执行与校验策略

| 等级 | 示例 | 默认交互 |
| --- | --- | --- |
| 只读 | 解释、审查、比较、定位 | 直接返回，附依据 |
| 可立即撤销的本地设置 | 主题、字号 | 执行并提供撤销 |
| Git 写操作 | 暂存、提交、切换、获取、拉取、合并、推送 | 目标明确且原有后端校验通过时直接执行 |
| 破坏性或含义不唯一 | 丢弃、删除分支、撤销、回滚、强制动作 | 必须指定对象；对象不明确或原有后端阻止时停止并说明原因 |

对于多步请求（例如“更新后合并并提交”），每一步执行前必须重新读取状态，不复用旧 revision。失败时停止，不自动尝试更危险的替代命令。当前实现仍只规划一个操作。

## 7. 设置与可观测性

- 现有“按操作设置系统提示词”扩展到能力注册表的 `promptKey`；保留默认文本、用户覆盖和“恢复默认”。用户提示词只改变生成策略，不改变 Oris 固定的工具权限、输出 schema 和安全校验。
- 可选为不同操作指定 AI 配置组合；未单独指定时使用全局当前组合。已加载的提示词包、识别出的操作、SOP 版本和模型选择可记录于操作日志。
- 记录本次意图、加载的 SOP、模型、预检失败原因、执行 opId 和实际结果；不记录 API Key，也不把完整 Diff 长期保存到日志。
- 对无 `@` 标签的自然语言保留“为何匹配此操作”的简短解释和切换操作入口；对带标签的请求显示实际加载的提示词包。无法确定时询问，不以模型自报的置信分数作为自动执行依据。

## 8. 分期交付与验收

1. **入口与协议**：更名“✦ AI”；实现 `@Git` / `@设置` 等提示词包菜单、按需注入、无标签意图识别、SOP 注册表、结构化计划和统一进度；接入现有提交与只读解释。验收重点：标签本身不触发写入，无标签误判也不触发写入，关闭规划框能取消 AI 调用。
2. **已有低风险能力**：接入暂存、切换分支、主题、字号、获取与审查；复用现有操作入口和权限校验。验收重点：过期 revision、歧义目标和工作区阻塞均在执行前拦截。
3. **复杂 Git 流程**：接入拉取、推送、合并、stash 和明确的撤销提交；完成多步逐步重验。验收重点：分叉、冲突、无上游、目标 OID 移动及取消后的状态如实呈现。
4. **新写能力**：先设计文件补丁与冲突解决的独立预览、备份和撤销接口，再开放 `@解决冲突`。`@回滚` 中尚未实现的 revert/reset 单独设计，不能借现有 `undoCommit` 冒充。

## 9. 已对齐与仍需决定的产品含义

1. 已对齐：`@xxx` 用于注入提示词和 SOP，不是必填命令或执行许可。`@Git`、`@设置` 是推荐的领域提示词包；`@提交`、`@合并` 可作为更具体的包。“切换主体”“更新”不预设为独立指令。
2. 待决定：自然语言一次提到多个动作时，是否允许生成多步计划？当前一次只规划一个操作；若后续支持多步，每步需复核状态。
3. 待决定：除内置 `@Git`、`@设置` 外，是否开放用户自定义只读 SOP；首期建议只允许编辑内置 SOP 的提示词，待工具权限和版本迁移成熟后再开放自定义。
