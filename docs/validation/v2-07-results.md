## 与技术方案的差异

见 [技术方案 §10.8](../architecture/v2-architecture.md#108-实施说明2026-09-29任务-v2-07)。要点：成员是带 `groupId` 的普通项目记录（存储仍为 v2）；嵌套仓库过滤对所有仓库生效；新增 `members` 事件；worktree 只有工作区根等于登记路径才算就绪；多个不可用 worktree 合并显示。

## 验收中发现并修复的问题

1. **添加工作区时当前项目被切回旧项目**（`da75a92`、`28a164c`）：添加流程先做一次异步发现，期间旧项目的自动刷新结果把当前项目设回去。先占用请求门控；并新增 `activeIntent`，修复一个既有竞态——当前仓库刚改变、界面尚未重新渲染时，“回到前台”计时器按闭包中的旧仓库刷新。工作区界面测试在高负载下约每 6–10 轮复现一次，修复后连续多轮未复现。
2. **指针开关在窗口不在前台时不生效**（`28a164c`）：开关走了受前台状态约束的自动刷新，改为直接重新扫描。
3. **指针行没有“记录 → 当前”**（`7aefae7`、`1ccf398`）：扫描为子模块条目带上两侧提交；“全部”范围补齐统计后保留。
4. **首次跳到子仓库时历史页先报“仓库尚未打开”，比较区给出错误的“缺少提交”说明**（`7aefae7`）：历史页改为仓库打开后才挂载。该问题对普通项目的首次切换同样存在，一并修复。
5. **真实工作区中 client 被重复列出、同名 worktree 占满列表**（`b08060c`）：client 登记了 8 个由其他工具创建、停在 `locked initializing` 的 worktree；目录还在但不是完整 worktree，Git 向上找到 client 本身。改为工作区根必须等于登记路径才算就绪，同名 worktree 带上级目录，多个不可用的合并成一行。
6. **历史跳转的比较请求会在回到子仓库时重复打开**（`da75a92`）：离开该子仓库后清除请求。

## 未验证与遗留

- macOS 未验证；真实系统焦点切换未验证（界面验收全部为 CDP 页面事件）。
- 验收计划 §3 的工作区预算、§4 内存预算未按正式方法在 S 数据集上测量；普通项目的首次打开、热切换、外部变化三项未与 V2-01 结果做回归对比。
- 选择器的“有变化”在读完改动数之后仍可能出现（读取后仓库又被外部修改），此时改动数可能已过期，界面如实显示两者。
- 普通项目（非工作区）中未跟踪的嵌套仓库目录也不再列为未跟踪文件，改在列表底部说明；这是有意的行为变化（见 §10.8）。
