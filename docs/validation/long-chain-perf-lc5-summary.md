# 长链 lc5 总结：发布性能测试与优化

日期：2026-09-30 至 10-01。任务：[长链 lc5](../tasks/onetime/long-chain-perf-lc5.md)。只验证 Windows。

## 结论

- **最终 main（`59670df`）上 V1 §4 与 V2 §3–§4 的全部性能、写操作、块操作、外观、分层内存与工作区预算都达标，没有降低或调整任何预算。** 完整发布性能会话（22 个套件，全部有效）在 `6de8b52`（构建 `B97C13B8…`）上；最终构建 `530D88CE…` 只多了一处界面状态修复，在它上面复测了打开与工作区两组（core 与 workspace，负载有效，全部达标：首次打开 P95 457.0、热切换 32.5、已缓存 / 未缓存 26.6 / 30.8 ms，打开工作区比普通项目多 P95 165.8 ms）。
- 例外：**外部变化 → 界面更新**未验证（需要真实前台焦点，AGENTS.md 不允许抢焦点）；失焦后内存“操作结束 3 s”口径为 [V2-D59](../decisions/v2-decisions.md) 已登记的已知限制（静置 65 s 口径达标）。
- 本轮修复 4 个问题，都是技术手段，不改体验：
  1. **阅读器主题在每次切换文件时重新创建**，样式表每次多 3 条规则且不回收，长时间使用后所有界面的样式重算都会变慢（v0.6.0 已有）。
  2. **大文件已缓存切换**（V2-D75 之后 1,813 块的文件 P95 超出 100 ms）：同机 A/B 96.6 → 81.7 ms，完整流程中 108–126 → 91.6 ms。
  3. **打开工作区**比普通项目多 366.8 ms（P95 差，预算 ≤ 300）→ 149.4 ms；普通项目首次打开 566.7 → 400.2 ms（V2-07 的成员发现）。
  4. **重新添加项目时旧错误残留**到成员发现结束（功能复验发现，V2-07 起）。
- 功能复验：14 个界面套件在最终构建上 13 个全部通过；`v1-06-projects --net-audit` 11/12，失败项是 WebView2 运行时自身的对外连接（已知，Oris 与 Git 没有对外连接，已写入发行说明）。
- **06 仍为 Awaiting acceptance**（签名、macOS 最终版本复测、AI 真实模型冒烟）。V2-07 已由用户验收（Done，Windows），本轮补上 §3 / §4 的实测。
