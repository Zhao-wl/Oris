## v0.6.0：相对 v0.5.0 的变化

- 变更列表的右键菜单增加“在资源管理器中打开”：文件在资源管理器中选中，目录直接打开；文件已删除时打开所在的上级目录。树状显示时目录行也有同样的菜单（PR #21）。
- 切换分支时，如果本地修改会被覆盖，改为给出三个选择：“放弃修改后切换”（修改先存入 stash 再从列表移除，结果给出 `git stash apply <OID>` 找回命令）、“带着改动切换”（`git switch --merge`，有冲突时照样切换并提示解决；有已暂存改动或未跟踪文件会被覆盖时不可用）、“取消”；原来的“stash 后切换”去掉（[V2-D87](../decisions/v2-decisions.md)，PR #23）。
- 历史页的分支右键菜单增加“切换到 …”与“检出为本地分支并切换”（PR #23）；打开历史页时分支列表自动定位到当前分支（PR #22）。
- V2-07 工作区由用户验收通过（2026-09-30，PR #20，只改文档）。

## v0.5.0：相对 v0.4.1 的变化

- **工作区**（[任务 V2-07](../tasks/v2/07-workspace.md)，V2-D76–V2-D86）：添加的仓库顶层 `.gitmodules` 中登记了子模块时，作为一个工作区添加，在项目栏只占一个标签（带“工作区”标识）。点击标题栏的仓库名或按 `Ctrl+E`（macOS `⌘E`）打开仓库选择器，在父仓库、子模块（只列一层）与它们的 linked worktree 之间切换；变更、diff、历史、分支、提交、stash、同步、合并、AI 都只作用于当前仓库。
  - 父仓库只显示自身的文件，不显示子仓库的内容；变更列表工具栏的“显示子模块指针变化”（按仓库保存，默认关闭）打开后，每个指针变化的子模块显示一行“记录 → 当前”，可暂存 / 取消暂存，不可丢弃。
  - 父仓库目录中未被跟踪的嵌套仓库（放在里面的 worktree、独立嵌套仓库）不进入变更列表，列表底部显示“N 个嵌套仓库未显示”，展开后可切换到属于工作区的成员；独立嵌套仓库默认不列入工作区，可在选择器中手动加入或移出。
  - 选择器中显示各仓库的分支、指针偏离与改动数（改动数在打开选择器时读取，最多同时 2 个 Git 进程，未读取的显示“未扫描”）；非当前仓库在外部变化后显示“有变化”，切换过去时刷新。
  - 父仓库历史中修改了子模块指针的提交可以“在子仓库中比较这两个版本”；子仓库缺少对应提交时说明原因，不自动获取。
  - 已作为独立项目添加的成员仓库在添加工作区时并入，保留别名、阅读位置与提交草稿；直接添加子模块目录时改为打开所属工作区并选中该仓库。各仓库的阅读位置、比较范围、提交草稿与指针开关分别保存，重启后恢复到上次选中的仓库。
  - 一个工作区共用一个文件监听：子仓库中的大量写入不会让父仓库重新扫描，非当前仓库只标记待刷新。
  - Oris 不执行 `submodule init / update / sync` 与 `worktree add / remove / prune`：未初始化的子模块、目录缺失的 worktree 灰色显示并给出命令行做法；不读取 `.gitmodules` 中的 `url`，绝对路径与越出仓库的路径被忽略。
- 行为变化（所有项目）：未被跟踪的嵌套仓库目录不再作为未跟踪文件列出（它们没有可读的 diff 内容），改为在列表底部说明。
- 修复：第一次切到某个项目（或工作区成员）时，历史页会先报“仓库尚未打开”；窗口回到前台时的自动刷新偶尔会按上一个项目刷新，把当前项目切回去。
- 修复：开启“对齐变化”时，块数很多的文件滚动停下后需要很长时间才能重新对齐（65 块约 2 s，几百块以上超过 30 s，期间块边界相差几十像素）；现在一轮计算全部间隔，停下后约 0.1–0.3 s 完成对齐（[研究 10 §7.5](../research/10-diff-scan-limit.md)）。
- 历史页“本地分支”分组的“清理…”：先对上游所在的 remote 获取并清理已删除的远端分支（`fetch --prune`，从不清理标签），再列出上游已消失的本地分支，确认后删除；未合并的分支会再次确认。获取失败时确认框会说明结果基于本地已知的远端状态。普通“获取”仍然不清理任何远端分支（[V2-D74](../decisions/v2-decisions.md)）。本地分支也可以右键“删除分支…”（当前分支不能删除）。
- 修复：在历史页选中某个分支浏览时，如果这个分支被删除（右键删除、“清理…”或在终端中删除），提交列表会停在“无法解析引用”；现在回到“全部分支”并提示该分支已不存在。
- 修复：开启“自动换行”和“对齐变化”时，有多个差异块的文件在两个块之间滚动，两侧的上下文行可能错开一到两行；现在保持对齐（[结果](../validation/wrap-align-results.md)）。
- 改进：改动分散的大文件不再整段显示为一个差异块（分级 diff，[V2-D75](../decisions/v2-decisions.md)）；块导航、折叠、词级高亮与差异块操作按实际改动分块。
- 修复：差异块标题行的标签与按钮在横向滚动时保持可见。

## 内容

一期（V1）与二期（V2）合并发布（[V2-D19](../decisions/v2-decisions.md)）：

- 多项目本地 Git 差异阅读：未暂存 / 已暂存 / 全部三个范围，并排与统一视图、词级高亮、折叠与逐段展开、搜索、同步滚动、软换行、专注模式、空白处理；图片对比（并排、滑动、缩放）与冲突版本（Base / Ours / Theirs / 工作区）只读查看；二进制、编码不支持、超预算、LFS 指针、子模块、符号链接、仅 mode 变化都有明确说明。

- 设置：外观（19 套配色方案、浅色 / 深色 / 跟随系统、字号）、Git 可执行文件路径、AI、更新。
- 可选的 AI 提交辅助与统一操作入口（见下文“AI”）。

## Git 要求

- 需要系统已安装 **Git 2.31.0 或更高版本**。Oris 不打包 Git，不自动安装开发工具。
- 默认从 `PATH` 自动发现 `git`（Windows 上从开始菜单 / 资源管理器启动时，使用系统与用户环境变量中的 `PATH`）。也可以在“设置 → Git”中指定 git 可执行文件的完整路径；新路径先校验版本，校验失败时保留原来的有效设置。
- 找不到 Git 或版本低于 2.31.0 时，打开项目会给出原因与处理方法（安装 / 升级 Git，或在设置中指定路径），不会显示为“没有变化”。
- 远端认证使用用户已有的 Git 凭据环境（Windows：Git Credential Manager；macOS：osxkeychain；SSH：ssh-agent）。Oris 不保存、不读取、不显示凭据；网络操作禁止 Git 在终端中询问凭据，需要首次交互认证（例如确认 SSH 主机指纹）时，请先在终端完成一次。

## 安全边界

- **普通浏览只读**：浏览、刷新、切换项目 / 范围 / 文件、查看历史、启动与快照恢复不修改工作区、index、refs、config（仅在限定时机由 Git 回写 index 的 stat 缓存，[V2-D09](../decisions/v2-decisions.md)）。只读读取禁用外部 diff、textconv、fsmonitor，不跟随越出仓库的符号链接，不修改 `safe.directory`。
- **fetch、pull、push 及其余写操作只由用户显式触发**；没有自动获取、自动拉取或定时同步。普通获取不清理远端分支；只有你点击“清理…”时才清理上游 remote 上已删除的远端分支（不清理标签，V2-D74）。
- **写操作会执行用户仓库的 hooks 与 filter**（与命令行 Git 一致，不提供 `--no-verify`）；签名按用户的 git config 执行。
- 丢弃前自动备份（单文件 ≤ 50 MiB，超出时确认框标注“不可撤销”）；写操作不自动重试；外部持有 `index.lock` 时报错且不删除锁；同步（获取 / 拉取 / 推送）遇到 Git 锁文件时列出锁文件与修改时间，由你确认后删除并重试一次（V2-D65）；不支持的进行中状态（rebase、cherry-pick、revert、bisect）下写操作全部禁用。
- 不收集遥测，不加载远程代码；界面资源全部打包在应用内（CSP 只允许应用自身资源）。
- 对外网络请求只有三类：你触发的 Git 同步、自动检查更新（访问 GitHub，可在“设置 → 更新”关闭）、你配置并触发的 AI 请求。
- WebView2 运行时自身可能联网：验收中偶尔看到 WebView2 运行时的网络服务进程（`msedgewebview2.exe`，`network.mojom.NetworkService`）连接 `150.171.27.11:443` 与 `113.249.87.135:80`（多数运行中没有）；同一时刻 Oris 与它启动的 Git 进程都没有对外连接。推测为 WebView2 运行时自身的组件更新或配置请求，不经 Oris 代码；请求内容与目的**未确认**。

## 内容预算

超出预算的内容显示明确的降级说明，不显示为“没有变化”：

| 内容 | 预算 |
| --- | --- |

## AI（可选，默认未配置）

- **默认不联网**：没有 AI 配置时，启动与日常使用不发出任何 AI 请求、不启动任何 AI 命令行工具。只有在你生成提交信息、发送 AI 指令或查询模型时才会联系你配置的服务（[V2-D66](../decisions/v2-decisions.md)、V2-D70）。
- **提供方**（设置 → AI）：本机的 OpenAI Codex CLI（`codex`）与 Claude Code（`claude`，使用你已登录的账号）；OpenAI、Anthropic、DeepSeek 与 OpenAI 兼容接口的 API。Base URL 必须为 HTTPS，只有本机地址可用 HTTP（V2-D71）。
- **API Key** 只保存在系统凭据存储（Windows 凭据管理器 / macOS 钥匙串，条目“Oris AI”），设置文件只记录“是否已保存”；删除配置时同时删除凭据。
- **发送的数据**（与“设置 → AI”中的说明一致，V2-D72）：
  - 生成提交信息：已暂存的文件列表与已暂存的改动（最多约 90 KB）。
  - 按描述选择文件提交：候选文件列表、已暂存与未暂存的改动（各最多约 90 KB）、未跟踪文件开头最多 2 KB（最多 40 个），合计最多约 18 万字符。
  - AI 指令：项目与分支名、未暂存 / 已暂存文件列表、分支与远端名称、当前打开文件两侧的内容（各最多 12,000 字符）、外观设置与已保存 AI 组合的名称和模型；指令提到 stash、丢弃记录、撤销提交或历史时，另附相应的说明、路径或提交标题与作者。
- **能做什么**：AI 提交辅助（生成提交信息后由你检查再提交）；统一操作入口（`Ctrl+P` / `⌘P`）把自然语言指令变成一个结构化计划，经白名单校验后执行 Oris 已有的 Git 操作、外观与 AI 设置或界面动作。有效计划直接执行，不再二次确认（V2-D69）。不提供任意 shell、Git 参数或文件写入。
- **不能做什么**：不能修改 Git 可执行文件路径（V2-D67）；不代替你确认——不可撤销的丢弃、撤销丢弃会覆盖之后的修改、文件仍含冲突标记时标记已解决等需要确认的操作会停止并提示用对应按钮操作（V2-D68）；仓库在规划后已变化时拒绝执行。多步计划与自定义 SOP 不在本次发布（V2-D73）。
- **命令行工具**在临时目录中运行（不在你的仓库中），Codex 为只读沙箱，Claude Code 不提供任何工具；取消或超时时结束整个进程树。超时：查询模型 15 s、HTTP 生成 120 s、命令行 300 s；网络错误、401 / 403、429 与无效输出都有中文说明，不自动重试。
- V2-D69–V2-D73 已由用户按现有实现确认（2026-09-29）。验收只用本机假服务与假命令行工具验证，**没有调用真实模型服务**；真实模型冒烟为发布前的用户待办。

## 已知限制

- **外部变化的自动刷新只在 Oris 窗口处于前台时进行**；窗口在后台时标记待刷新，切回后刷新（也可随时“本地刷新”）。
- 双层修改抵消判断按字节比较，不应用 clean filter / EOL 转换：配置了转换的仓库中，实际无变化的文件可能留在“全部”范围。
- `.gitignore` 变化后，“已跟踪但被忽略”的文件清单要到重新打开项目才重算。
- 不支持 fsmonitor 加速；十万文件级仓库的 status 约 150–200 ms。
- 差异块操作在“全部”范围、忽略空白、冲突、二进制、只有一侧可读、新增 / 删除整个文件时不可用（均有原因说明）；非 UTF-8 文件需要先选择“按单字节显示”。
- 拉取不执行 rebase（`pull.rebase=true` 时界面说明并仍以合并执行）；不提供强制推送、交互式 rebase、cherry-pick、submodule 更新等操作。
- stash 列表最多 500 条；Git 拒绝切换分支时只列出 Git 输出中的前若干路径。
- 推送预览中的“领先 N 个提交”来自本地快照，不代表服务器实时状态。
- 性能与内存（Windows 实测，v0.6.0 之后的最终 main，见 [lc5 发布性能报告](../validation/v1-06-performance-lc5.md)）：V1 与 V2 的全部性能、写操作、块操作、外观、分层内存与工作区预算达标。已知问题：窗口失焦后内存需要静置一段时间才回落到目标值（静置 65 s 口径达标，操作刚结束 3 s 的口径受 WebView2 回收时机影响，[V2-D59](../decisions/v2-decisions.md)）；“外部变化 → 界面自动更新”的时延未测（需要真实前台焦点）。macOS 未测。
- ~~“对齐变化”（默认关闭）在块数很多的文件中滚动后需要较长时间才重新对齐完成~~：v0.4.1 之后已修复（一轮计算全部间隔，540 / 1,813 块的文件停下后 113 / 281 ms 完成、可见误差 0，[研究 10 §7.5](../research/10-diff-scan-limit.md)）。
- 块数很多（上千块）的大文件：v0.6.0 之后已缓存切换达标（10,000 行、1,813 个差异块的文件 P95 约 90 ms，个别样本约 140–180 ms）；v0.6.0 中这类文件在长时间使用后会越来越慢（见下文“v0.6.0 之后”）。
- 工作区：Oris 不初始化、更新子模块，也不创建、删除 worktree（需在命令行操作）；子模块的子模块不作为成员，在子仓库中按指针显示；不提供跨仓库的批量操作与合并视图。选择器中的改动数在读取后如果仓库又被外部修改，可能已过期（同时显示“有变化”）。macOS 未验证。
- ~~自动换行开启且两侧对齐时，少数长行的滚动对齐存在既有误差~~：v0.4.1 之后已修复（有多个差异块的文件中，视口落在两块之间时两侧上下文行不再错开，见 [换行 + 对齐结果](../validation/wrap-align-results.md)）；原先记录的 73.1 px 是视口外的连接带端点，看不到。

## 安装与卸载

**Windows（内部测试包）**

- 运行 `Oris_<版本>_x64-setup.exe`。安装程序**未签名**，Windows SmartScreen 可能提示“未知发布者”；这是本轮内部测试包的已知状态，不要为此关闭系统保护。
- 按当前用户安装（不需要管理员权限）到 `%LOCALAPPDATA%\Oris`，并创建开始菜单快捷方式。
- 安装目录中有 `oris.exe`、`WebView2Loader.dll`（WebView2 加载器）与 `THIRD-PARTY-NOTICES.txt`（第三方组件许可证全文，含 VS Code 与 Colorsublime 配色声明）。

## v0.6.0 之后（未发布）

随下一版本发布（main `59670df` 起；性能数据见 [lc5 发布性能报告](../validation/v1-06-performance-lc5.md)）：

- 修复：长时间使用后切换文件越来越慢。阅读器的一个固定主题在每次切换文件时都会重新创建，向样式表追加规则且不回收（每切换一次多 3 条），样式重算随使用时间变慢；现在只创建一次。
- 改进：块数很多的大文件切回时更快：已缓存的文件切换少做重复的编辑器配置、事务派发与强制布局，概览轨道的标记整层重建；10,000 行、1,813 个差异块的文件 P95 从约 108–126 ms 降到约 90 ms（[lc5 优化结果](../validation/perf-optimize-lc5-results.md)）。
- 改进：打开工作区更快：成员发现少启动约一半的 Git 进程，各成员“已跟踪但被忽略”的清单改为依次计算、不再与打开父仓库同时扫描，增删统计不再进入子模块检查改动。8 个成员的工作区比同规模普通项目只多约 150 ms（原约 370–460 ms），首次切到成员约 0.3 s（原约 0.9 s）；普通项目的首次打开也更快（P95 约 400 ms）。
- 修复：添加项目失败后再次添加时，上一次的失败说明会一直显示到成员发现结束（v0.5.0 起；工作区约 0.1–0.6 s），现在开始添加时立即清除。
