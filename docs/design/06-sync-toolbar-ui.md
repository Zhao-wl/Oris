# 同步工具栏改版参考图

状态：**用户已确认，已实施**（2026-09-28，V2-D64）。实现与效果图的差异见文末“实施说明”。起因是用户对 V2-04 同步功能的反馈：入口层级深、三个确认框风格不统一且没有实际决策、“同步”弹层打开有等待。依据 [研究 09](../research/09-git-sync-interaction.md)。用户已选定：三个独立按钮、拉取默认仅快进（分叉时询问）、暂不做自动获取。

[打开可交互效果图](oris-sync.html)

## 改动要点

1. 标题栏用 `⟳ 获取 · X 分钟前 ▾`、`↓n 拉取 ▾`、`↑n 推送 ▾` 三个分体按钮，取代“⇅ 同步 ▾”弹层和标题栏单独的 `↑ ↓` 计数。
2. 点主按钮直接执行，不再弹出说明型确认框：
   - 获取：获取当前分支上游所属的 remote；没有上游时获取唯一的 remote。有多个 remote 且无上游时，才在 ▾ 中选择。
   - 拉取：按本仓库记住的方式执行，默认仅快进。
   - 推送：推到上游。没有上游时按钮显示“发布分支”：只有一个 remote 就直接推送并设为上游，有多个 remote 才弹窗选择。
3. ▾ 选项：
   - 获取：列出 remote。
   - 拉取：“仅快进 / 合并远端改动”单选，选中即设为本仓库默认；另有“更换上游…”。
   - 推送：预览要推送的提交。
4. 只保留真正需要决定的弹窗，统一为一种样式（标题、一段说明、取消 + 主按钮）：
   - 已分叉时询问“改用合并拉取”，可勾选“以后都用合并”。
   - 工作区改动会被覆盖时询问“储藏后拉取”。
   - 首次推送且有多个 remote 时选择 remote。
   - 更换上游。
5. 执行中：按钮变为“获取中… ✕ 取消”，再点一次即取消；其他两个按钮暂不可用；状态栏提示详情见“操作输出”。界面不被遮挡。
6. 结果用右下角提示：
   - 成功 4 秒后消失。
   - 失败保留，并附下一步动作：推送被拒时给“拉取”，认证失败时给“重试”。
   - 取消时说明已写入的远端跟踪引用不回滚。
7. 不可用状态放在按钮悬停说明里：分离 HEAD 时拉取、推送不可用；没有上游时拉取不可用。

## 行为不变

不做 rebase，配置了 `pull.rebase` 也以合并执行；不做强制推送；不推送 tag；不递归子模块；不自动获取。git 参数、进度、取消、无输出超时、认证处理沿用 V2-04 后端实现。

## 实现备注（非界面）

- 按钮状态只取当前快照的 `branchInfo`（上游、领先 / 落后、HEAD）。点击和打开 ▾ 时不再调用 `readRefs`。旧弹层每次打开都要跑 `for-each-ref … %(upstream:track)`，要给所有本地分支计算领先 / 落后数，这是分支多的仓库里打开要等待的原因。
- 只有推送 ▾ 的提交预览和多 remote 选择需要额外读取，在展开时按需读取，并显示占位。
- `FetchDialog`、`PullDialog`、`PushDialog` 与 `SyncPopover` 删除；决策弹窗共用一个组件。
- 拉取默认方式按仓库保存在应用数据中；“以后都用合并”写同一项。

效果图不执行 Git，领先 / 落后数、提交列表、耗时均为演示数据。未覆盖浅色主题、键盘快捷键与合并进行中的横幅（沿用现有）。

## 实施说明（2026-09-28）

- 默认 remote 由后端决定：`fetch` / `push` 请求可以不带 remote。后端取当前分支上游所属的 remote，没有上游时取仅有的一个 remote；有多个 remote 而无法确定时返回 `chooseRemote` 确认，界面弹出选择框后带上所选 remote 重试。一键执行不需要先读取 refs。
- 推送 ▾ 只显示目标与领先的提交数，没有列出提交：现有日志接口不能表达“本地有、上游没有”的范围。
- 分叉询问框没有加“以后都用合并”复选框，改为在说明里提示去“拉取 ▾”中修改默认方式。
- 获取 ▾ 用新的轻量读取 `read_remotes` 列出 remote。它只运行 `git remote` 和一次 `for-each-ref`，不读分支与领先 / 落后。client-x20-x 实测：`read_refs` 0.8–4.7 s（随负载波动），`read_remotes` 约 0.3 s，获取 ▾ 打开从 3.4 s 降到 0.27 s。`read_refs` 在应用内比命令行慢得多，原因待查。
- “获取”按钮上的时间取 Oris 记录与 `FETCH_HEAD` 中较新的一次；`FETCH_HEAD` 的时间在打开获取 ▾ 或历史页后才知道。
- 结果提示放在底部 Git 页签栏之上，不遮挡“展开 / 收起”。
- 标题栏原来单独的 `↑ ↓` 计数与“无上游”标记已并入按钮。AI 的“打开获取 / 拉取 / 推送”动作改为展开对应的 ▾。
