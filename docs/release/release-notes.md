## Git 要求

- 需要系统已安装 **Git 2.31.0 或更高版本**。Oris 不打包 Git，不自动安装开发工具。
- 默认从 `PATH` 自动发现 `git`（Windows 上从开始菜单 / 资源管理器启动时，使用系统与用户环境变量中的 `PATH`）。也可以在“设置 → Git”中指定 git 可执行文件的完整路径；新路径先校验版本，校验失败时保留原来的有效设置。
- 找不到 Git 或版本低于 2.31.0 时，打开项目会给出原因与处理方法（安装 / 升级 Git，或在设置中指定路径），不会显示为“没有变化”。
- 远端认证使用用户已有的 Git 凭据环境（Windows：Git Credential Manager；macOS：osxkeychain；SSH：ssh-agent）。Oris 不保存、不读取、不显示凭据；网络操作禁止 Git 在终端中询问凭据，需要首次交互认证（例如确认 SSH 主机指纹）时，请先在终端完成一次。

## 安全边界

- **普通浏览只读**：浏览、刷新、切换项目 / 范围 / 文件、查看历史、启动与快照恢复不修改工作区、index、refs、config（仅在限定时机由 Git 回写 index 的 stat 缓存，[V2-D09](../decisions/v2-decisions.md)）。只读读取禁用外部 diff、textconv、fsmonitor，不跟随越出仓库的符号链接，不修改 `safe.directory`。
- **fetch、pull、push 及其余写操作只由用户显式触发**；没有自动获取、自动拉取或定时同步。
- **写操作会执行用户仓库的 hooks 与 filter**（与命令行 Git 一致，不提供 `--no-verify`）；签名按用户的 git config 执行。
- 丢弃前自动备份（单文件 ≤ 50 MiB，超出时确认框标注“不可撤销”）；写操作不自动重试；外部持有 `index.lock` 时报错且不删除锁；同步（获取 / 拉取 / 推送）遇到 Git 锁文件时列出锁文件与修改时间，由你确认后删除并重试一次（V2-D65）；不支持的进行中状态（rebase、cherry-pick、revert、bisect）下写操作全部禁用。
- 不收集遥测，不加载远程代码；界面资源全部打包在应用内（CSP 只允许应用自身资源）。
- 对外网络请求只有三类：你触发的 Git 同步、自动检查更新（访问 GitHub，可在“设置 → 更新”关闭）、你配置并触发的 AI 请求。

## AI（可选，默认未配置）

- **默认不联网**：没有 AI 配置时，启动与日常使用不发出任何 AI 请求、不启动任何 AI 命令行工具。只有在你生成提交信息、发送 AI 指令或查询模型时才会联系你配置的服务（[V2-D66](../decisions/v2-decisions.md)、V2-D70）。
- **提供方**（设置 → AI）：本机的 OpenAI Codex CLI（`codex`）与 Claude Code（`claude`，使用你已登录的账号）；OpenAI、Anthropic、DeepSeek 与 OpenAI 兼容接口的 API。Base URL 必须为 HTTPS，只有本机地址可用 HTTP（V2-D71）。
- **API Key** 只保存在系统凭据存储（Windows 凭据管理器 / macOS 钥匙串，条目“Oris AI”），设置文件只记录“是否已保存”；删除配置时同时删除凭据。
- **发送的数据**（与“设置 → AI”中的说明一致，V2-D72）：
  - 生成提交信息：已暂存的文件列表与已暂存的改动（最多约 90 KB）。
  - 按描述选择文件提交：候选文件列表、已暂存与未暂存的改动（各最多约 90 KB）、未跟踪文件开头最多 2 KB（最多 40 个），合计最多约 18 万字符。
  - AI 指令：项目与分支名、未暂存 / 已暂存文件列表、分支与远端名称、当前打开文件两侧的内容（各最多 12,000 字符）、外观设置与已保存 AI 组合的名称和模型；指令提到 stash、丢弃记录、撤销提交或历史时，另附相应的说明、路径或提交标题与作者。
- **能做什么**：AI 提交辅助（生成提交信息后由你检查再提交）；统一操作入口（`Ctrl+P` / `⌘P`）把自然语言指令变成一个结构化计划，经白名单校验后执行 Oris 已有的 Git 操作、外观与 AI 设置或界面动作。有效计划直接执行，不再二次确认（V2-D69）。不提供任意 shell、Git 参数或文件写入。
- **不能做什么**：不能修改 Git 可执行文件路径（V2-D67）；不代替你确认——不可撤销的丢弃、撤销丢弃会覆盖之后的修改、文件仍含冲突标记时标记已解决等需要确认的操作会停止并提示用对应按钮操作（V2-D68）；仓库在规划后已变化时拒绝执行。多步计划与自定义 SOP 不在本次发布（V2-D73）。
- **命令行工具**在临时目录中运行（不在你的仓库中），Codex 为只读沙箱，Claude Code 不提供任何工具；取消或超时时结束整个进程树。超时：查询模型 15 s、HTTP 生成 120 s、命令行 300 s；网络错误、401 / 403、429 与无效输出都有中文说明，不自动重试。
- V2-D69–V2-D73 为“待用户决定（按现有实现先行）”，发布前需要确认；本轮验收只用本机假服务与假命令行工具验证，**没有调用真实模型服务**。

## 已知限制

- **外部变化的自动刷新只在 Oris 窗口处于前台时进行**；窗口在后台时标记待刷新，切回后刷新（也可随时“本地刷新”）。
- 双层修改抵消判断按字节比较，不应用 clean filter / EOL 转换：配置了转换的仓库中，实际无变化的文件可能留在“全部”范围。
- `.gitignore` 变化后，“已跟踪但被忽略”的文件清单要到重新打开项目才重算。
- 不支持 fsmonitor 加速；十万文件级仓库的 status 约 150–200 ms。
- 差异块操作在“全部”范围、忽略空白、冲突、二进制、只有一侧可读、新增 / 删除整个文件时不可用（均有原因说明）；非 UTF-8 文件需要先选择“按单字节显示”。
- 拉取不执行 rebase（`pull.rebase=true` 时界面说明并仍以合并执行）；不提供强制推送、交互式 rebase、cherry-pick、submodule 更新等操作。
- stash 列表最多 500 条；Git 拒绝切换分支时只列出 Git 输出中的前若干路径。
- 推送预览中的“领先 N 个提交”来自本地快照，不代表服务器实时状态。
- 性能与内存（Windows 实测，见 [RC 验收结果](../validation/v1-06-rc-results.md)）：RC 构建上的打开、重启、切换、文件、stage / unstage / commit 预算全部达标；字号切换已优化（V2-D58）；写操作、块操作与分层内存本轮未在 RC 构建上复测。已知问题：窗口失焦后内存需要静置一段时间才回落到目标值（静置 65 s 口径全部达标，操作刚结束 3 s 的口径受 WebView2 回收时机影响，[V2-D59](../decisions/v2-decisions.md)）。macOS 未测。
- ~~自动换行开启且两侧对齐时，少数长行的滚动对齐存在既有误差~~：v0.4.0 之后已修复（有多个差异块的文件中，视口落在两块之间时两侧上下文行不再错开，见 [换行 + 对齐结果](../validation/wrap-align-results.md)）；原先记录的 73.1 px 是视口外的连接带端点，看不到。

## 安装与卸载

**Windows（内部测试包）**

- 运行 `Oris_<版本>_x64-setup.exe`。安装程序**未签名**，Windows SmartScreen 可能提示“未知发布者”；这是本轮内部测试包的已知状态，不要为此关闭系统保护。
- 按当前用户安装（不需要管理员权限）到 `%LOCALAPPDATA%\Oris`，并创建开始菜单快捷方式。
- 安装目录中有 `oris.exe`、`WebView2Loader.dll`（WebView2 加载器）与 `THIRD-PARTY-NOTICES.txt`（第三方组件许可证全文，含 VS Code 与 Colorsublime 配色声明）。
- 本轮没有在本机执行安装 / 卸载测试（未授权）；步骤见 [Windows 安装 / 卸载交接清单](windows-install-checklist.md)。
- 卸载：“设置 → 应用 → 已安装的应用”中卸载 Oris，或运行安装目录中的卸载程序。**卸载不会删除你的 Git 仓库**（Oris 只登记仓库路径，从不移动或删除仓库）。卸载程序提供“删除应用数据”选项，默认不勾选；不勾选时下文的应用数据保留，重新安装后项目列表与设置恢复。

**macOS**：DMG 拖入“应用程序”安装，拖到废纸篓卸载；卸载同样不删除仓库。应用数据保留在下表位置，需要时手动删除。（macOS 安装包本轮未构建，见交接清单。）
