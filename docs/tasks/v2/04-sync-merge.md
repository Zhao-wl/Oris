# V2-04 — 远端同步与合并

状态：Pending（未开始）。依赖：V2-02、V1 03（冲突只读查看）、V1 04（fetch、上游与领先/落后数、分支视图）。

## 用户闭环

作为用户，我可以把远端的更新拉下来、把本地提交推上去，也可以把另一个分支合并进来；出现冲突时，我能在 Oris 里看清冲突，在外部工具中解决后回到 Oris 标记已解决并完成合并，或者直接中止合并。

## 范围

- **R-SYNC**：pull（仅快进 / 合并，始终 `--no-rebase`，`pull.rebase` 配置提示，仅快进失败时可改用合并，“stash 后拉取”）；push（首次设置上游、选择 remote、被拒绝时提示先拉取）；fetch 接入统一的进度与取消；无输出超时；认证失败的提示；工具栏的同步按钮与领先/落后数。
- **R-MERGE**：合并选中分支（遵循 `merge.ff`，可选“总是创建合并提交”）；合并进行中横幅；查看冲突（跳转到 V1 03 的只读冲突阅读）；标记已解决（冲突标记检查）；完成合并；中止合并。
- **不支持的进行中状态**：rebase、cherry-pick、revert、bisect 进行中时禁用写操作并显示横幅。
- 凭据验证：两个平台分别用已有的凭据环境验证 HTTPS（GCM / osxkeychain）与 SSH（ssh-agent）；如果常见场景无法使用，提出 askpass 方案交用户决定，而不是在本任务内自行加上（V2-D12）。
