# 变更集 AI 审查（#26）

入口沿用 AI 临时对话：输入 `@审查`，选择范围、勾选变化文件，按需填写调用方、配置或测试的仓库相对路径，再发送。模型与提示词沿用该指令的现有路由。内置审查固定只读，导入的 action 模式也不能改变此约束。

- **工作区**：HEAD 到工作树最终内容，包含未跟踪文件；不把暂存与未暂存 patch 叠加成一个虚构结果。
- **暂存区**：HEAD 到 index；补充文件也从 index 读取。
- **指定提交**：第一父提交到选定提交；根提交从空树比较。合并提交按第一父提交审查，其他父提交可用分支比较选定 OID。
- **分支比较**：两端引用解析成 OID 后直接比较，不默认为 merge-base 比较，不混入本地修改。

每轮含补充文件最多 16 个，差异与带行号原文的 UTF-8 文本预算为 40,000 字节（不包括身份与来源元数据）。单份原文/patch 上限 5,000 字节；差异最多占总预算的一半。可选择较少文件重新审查以取得更多上下文。选择器最多列出前 1,000 个变化路径并显示真实总数；未勾选路径不发送给模型。没有进行全仓库搜索或自动上传。

结构化问题含触发条件、影响、原文依据、建议。源标识只能映射到实际传入的原文行；路径、侧别、端点、contentId 由应用提供，模型不能替换。无效问题标为未核实且不能点击。点击前重读端点身份及内容，验证仓库、路径、侧别和原文；使用现有 diff 阅读器显示，并跳转原始行号。只读定位视图不提供 hunk 写入。切回本地范围会重读本地内容。

缺文件、冲突、非文本与预算截断均有可见反馈。上下文形成后及模型返回后校验快照/内容；过期状态拒绝结果。取消或关闭丢弃迟到结果，提供方错误保持原始失败原因。输出和源码都作为文本数据；生成链路必须使用 `kind=answer`，操作计划会在后端和前端被拒绝。

提交组织建议仅覆盖实际读取的变化文件。同一文件混合改动需手动整理，本轮不执行行级补丁或提交，也不接入 #24/#25 撤销的 API。问题、影响、提交建议及来源摘要回到原有会话历史和复制入口，普通后续问答仍由原来的主模型处理。

实现：前端在本目录；后端在 `src-tauri/src/git/ai_review.rs`，复用 scan、历史比较、ContentReader 与只读命令工厂；模型复用 `plan_ai_action`、原有连接、进程隔离与取消机制。验收证据在 [validation/README.md](validation/README.md)。
