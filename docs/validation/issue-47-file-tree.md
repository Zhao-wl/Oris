# 文件筛选和目录树重复计算

面板原先在 `App.tsx` 的每次渲染中分别筛选和排序两个范围。活动范围同时为阅读选择维护一份筛选结果。面板列表现在按快照和筛选条件缓存，活动的暂存或未暂存范围复用相应结果。旧的单范围快照、全部范围和写入后的阅读位置仍遵循各自原有的来源。批量暂存继续读取未经筛选的范围。

`FileTree.tsx` 原先为 Shift 区间和渲染分别排序平铺列表、分别构造变更目录树。现在平铺列表共用排序结果，树形列表共用同一棵目录树。Shift 仍按目录的完整顺序定位，目录展开和收起保留原行为。折叠区只在打开时构造自己的树，目录名在本地化比较中并列时保留原始插入顺序。

## 同机前后对照

在同一台 Windows 主机、同一无头 Edge 会话中加载生产模式的 React 和实际 `FileTree`，仅替换该组件的新旧源码。视口 1440 × 900，列表容器高 360 px。每种规模将文件均分成两组，交替筛选，确认屏幕上的行均来自目标组。每组先预热 6 次，再交替测量前后各 30 次。计时范围为路径过滤与 React 同步 DOM 提交，包含列表虚拟化；App 的范围缓存、Git IPC 和浏览器绘制未计入。数据与 [桌面端到端基线](./issue-43-change-set-baseline.md) 使用不同口径。

| 模式 | 文件数 | 修改前 P50 / P95（ms） | 修改后 P50 / P95（ms） |
| --- | ---: | ---: | ---: |
| 平铺 | 100 | 2.4 / 3.2 | 1.9 / 3.5 |
| 平铺 | 1,000 | 14.9 / 24.3 | 13.7 / 23.7 |
| 平铺 | 5,000 | 1.8 / 2.6 | 1.9 / 2.5 |
| 树形 | 100 | 2.7 / 3.9 | 2.4 / 3.5 |
| 树形 | 1,000 | 16.2 / 20.7 | 12.8 / 20.2 |
| 树形 | 5,000 | 3.3 / 5.3 | 2.8 / 4.0 |

筛选后 1,000 文件组仍走普通列表，而 5,000 文件组进入虚拟列表。这解释了两组耗时的量级差异。5,000 文件树形 P95 减少 1.3 ms，平铺差异在这次样本中很小。保留结构复用，暂不将目录索引做成额外缓存，也未推断原生端到端加速比例。
