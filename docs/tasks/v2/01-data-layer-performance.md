## 用户闭环

作为用户，我打开、重开、切换项目，切换文件和显示区域时都几乎不需要等待；外部工具大量写文件时界面保持流畅；长时间使用后内存不持续增长。

## 范围

- **先测基线**：在当前 main 上按 [V2 验收计划 §3–§4](../../validation/v2-acceptance.md) 测量 V1 基线，并固定预算，然后再动代码。
- **StatusScanner**：用 `status --porcelain=v2 -z --branch --untracked-files=all` 替换现有 4 条命令；三个范围共享一个 revision，由前端过滤；“全部”范围懒执行 rename 修正；统计在后台补齐；解析 inProgress 标记。
- **ContentReader**：每个仓库一个常驻 `cat-file --batch` 进程（上限、空闲回收、异常恢复一次）；工作区直接读取；去掉 `READ_SERIAL`，改为每仓库队列与 generation 取消；冲突 stage 读取迁移到这里；大内容以二进制 IPC 传输。
- **缓存**：后端 OID BlobCache；前端 DiffCache 改为按 contentId 建键，不再整仓清空。
- **Watcher**：后端合并、gitignore 过滤、事件分类、后台项目只标记 dirty、watcher LRU 上限。
- **快照恢复**：持久化轻量状态，启动时显示“校验中”，完成后替换差异；为后续任务提供“校验前禁写”的状态标志。
- **stat 缓存回写**：手动刷新时回写（写操作后的回写由 V2-02 接入）。
- **前端**：按项目拆分 store、单编辑器实例复用、相邻预取、连续切换延迟请求、列表虚拟化。
- fsmonitor（V2-D10）不在本任务范围内，只记录 L 数据集的 status 时延作为后续决策依据。
