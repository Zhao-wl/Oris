# V2-07 — 工作区（父仓库 + 子仓库）

状态：Done（Windows，2026-09-30 用户验收通过，[结果](../../validation/v2-07-results.md)；PR #19 已合入 main）：B31–B36 自动化与界面验收通过，真实工作区只读冒烟通过；验收中修复 6 个问题。未验证：macOS、真实焦点、§3 / §4 预算的正式复测。依赖：V2-01（数据层、watcher）、V2-06（颜色变量）、V1 04（历史与版本比较）；均已完成（Windows）。决策：V2-D76–V2-D86。

## 用户闭环

作为用户，我在一个父仓库下挂着 client、battle、gdconfig 等多个子仓库。我把父仓库目录作为一个项目添加，Oris 识别出这是工作区；我在标题栏的仓库选择器中切换到 client，变更、历史、分支、提交、同步都只针对 client；切回父仓库时，只看到父仓库自己的文件，看不到子仓库的内容，也看不到被我放在里面的 worktree 目录。

## 范围

按顺序交付，每一步都可以单独验证：

1. **效果图**（V2-D86）：项目标签的工作区标识、仓库选择器（成员分组、worktree 缩进、徽标、未初始化 / 缺失的灰色状态、手动加入 / 移出）、子模块指针开关、变更列表底部的嵌套仓库说明、历史中的 gitlink 条目、快捷键。放在 `docs/design/07-workspace-ui.md`，用户确认后再做界面。
2. **发现与归属**（技术方案 §10.2）：`discover_group` 只读命令，识别工作区、成员、未初始化、worktree、缺失；直接添加子模块或子模块 worktree 时找到所属工作区。`.gitmodules` 路径校验（§8）。
3. **项目记录**（§10.3）：v3 存储与 v2 迁移；添加时合并已有的独立成员项目；按成员保存锚点与开关；恢复上次选中的成员。
4. **切换与作用范围**（§10.7）：仓库选择器；所有按 repoId 取状态的界面改为取“当前仓库”；切换成员复用项目切换路径。
5. **父仓库排除子仓库**（§10.4）：`--ignore-submodules` 按开关传入；嵌套仓库目录移到 `nestedRepos`；指针行与“切换到该仓库”。
6. **watcher 共用与分派**（§10.5）：`GroupWatcher`、最长前缀分派、非当前成员只标记 dirty、成员列表随 `.gitmodules` / worktree 变化更新。
7. **徽标**（§10.6）：分支 / 偏离在打开时读取，改动数在打开选择器时读取（并发 ≤ 2），未读取显示“未扫描”。
8. **历史联动**（V2-D85）：父仓库历史中的 gitlink 条目跳转到子仓库的版本比较。

## 交付与排除

工作区识别、成员切换、按仓库显示与操作、父仓库排除子仓库、子模块指针开关、嵌套仓库说明、徽标、历史中的 gitlink 跳转。

不包含：submodule add / init / update / sync / deinit，worktree add / remove / prune，跨仓库批量操作（一次对多个仓库暂存、提交、切换分支、获取、拉取），跨仓库合并显示的变更或历史视图，子模块的子模块成员（在子仓库中按 gitlink 显示），读取 `.gitmodules` 中的 `url`。
