# Oris V1 产品规格

状态：V1 功能基线；实施未开始。日期：2026-09-22。

## 1. 定位与主路径

Oris 帮助用户快速回答：哪个项目变了、哪些文件变了、具体改了什么、这些变化与哪个提交/分支有关。首要体验是易读的 diff，而不是提供更多 Git 命令。

最短主路径：添加已有仓库 → 查看本地变化 → 选择文件 → 看懂差异 → 切换另一项目 → 返回原阅读位置。

历史主路径：选择分支/提交 → 查看变化文件 → 阅读 diff → 比较另一版本或追溯文件历史。分支选择不改变实际工作分支。

支持 Windows 11 x64、macOS 14+ arm64（Apple Silicon M1 及以上）；不发布 Intel macOS 或 Universal 包。使用本机 Git，不随应用打包 Git。Git 缺失/不可用时说明问题并提供路径设置，不自动安装开发工具。

## 2. 需求与用户故事

每个编号是需求组；下列条目均需覆盖，任务数量不等于需求数量。

### R-PROJECT：多项目管理

- 作为同时查看多个代码仓库的用户，我能添加已有本地仓库，并识别名称、完整路径和实际当前分支。
- 我能固定、取消固定、查看最近项目、搜索并快速切换；同名不同路径不会混淆，同一仓库重复添加不会产生重复项。
- 我能从 Oris 列表移除项目；操作只删除应用记录，不删除目录，不改仓库。
- 切换项目或重新启动后，恢复各项目的视图、比较对象、选中文件和阅读锚点。对象已失效时清楚说明，退回合法入口，不显示旧内容冒充新内容。
- 非当前项目不常驻完整 diff；项目徽标可显示已知状态，但必须区分尚未扫描/旧状态，不能把未知当成零变化。

### R-LOCAL：本地变化

- 我能分别查看未暂存（Index → Working Tree）、已暂存（HEAD → Index）、全部本地改动（HEAD → Working Tree）。
- 同一文件可同时存在已暂存和未暂存变化，每个入口显示各自正确内容；全部本地改动不是两份 patch 的拼接。
- 未跟踪文件独立标识，可作为“无旧版本 → 当前内容”阅读，不伪装成 Git 已跟踪文件；默认不列 ignored 文件。
- 展示新增、修改、删除、重命名及冲突状态；重命名包含旧/新路径。冲突可以说明不能生成普通双端 diff，不提供解决冲突功能。
- 未产生首个提交时，空 HEAD 不导致整个应用失败，已暂存内容可相对空树阅读。
- 外部工具修改文件、暂存、提交或切换分支后，Oris 更新状态；刷新失败显示错误及旧数据标志，不误报无变化。

### R-FILES：文件导航

- 目录树/平铺列表、路径搜索、状态标识、文件数量和可得的文本增删统计。
- 选择文件、键盘前后文件导航、复制路径；无匹配、无变化、未加载和读取失败分别表达。
- 中文、空格、特殊字符及长路径应正确显示；路径不可解码时仍保留可读取的内部标识。

### R-DIFF：文本差异阅读

- 并排/统一切换；原始/新版本及比较方向常驻。
- 修改蓝、新增绿、删除灰；行内词级高亮和按行高亮可切换；用符号/文本辅助颜色。
- 双侧对应关系、中央连接带、同步滚动、前后差异导航、变化位置计数正确。
- 上下文折叠/逐段展开/全部展开、长行软换行、语法高亮、文本搜索和选择复制。
- 空白规则至少支持保留和忽略空白；忽略规则持续可见，差异计数/高亮/导航使用同一阅读结果。
- 字体/字号、浅深主题、专注 diff。只读文本组件不提供修改、保存、Accept、Revert 或 Apply 操作。
- 编码、换行、仅换行变化、无末尾换行有明确状态；不能因解码失败显示无差异。
- 大文件/长行超预算时显示原因和已显示范围，保留返回/切换能力，不默默截断或冻结。

### R-HISTORY：提交历史

- 提交列表与紧凑拓扑；显示消息、作者、时间、SHA、分支/标签/HEAD。
- 搜索消息、作者、SHA，按分支筛选；跳到 HEAD。分批加载不改变已显示提交的身份及选择。
- 选中提交显示元信息、父节点、变化文件及 diff；根提交相对空树，合并提交明确当前父节点并允许选择父节点。
- 历史图基于真实 parents/OID，不使用页面行号推断拓扑。分页边缘未加载的关系有延续标识。

### R-BRANCH：分支浏览

- 查看本地/远端跟踪分支、上游、当前工作分支；选择分支仅筛选历史。
- 显示相对明确上游的 ahead/behind；无上游、上游已失效、数据未知分别表达，不填 0/0。
- 计数基于本地引用快照，不宣称服务器实时状态；ahead 默认表达“领先上游”，不保证等于不同 push 配置下的实际待推送数。

### R-COMPARE：版本比较

- 选择任意两个提交或分支，显示 A → B 的变化文件并进入同一 diff；可交换方向。
- 选择分支后解析为确定 OID，比较期间 ref 移动不悄悄替换端点，提示可刷新。
- V1 必须有直接端点比较；共同基线模式不是本轮必需项，不能把 direct 与 merge-base 语义混用。

### R-FILEHISTORY：单文件追溯

- 从文件入口查看该路径相关提交，选择版本阅读其变化，并可返回原比较位置。
- 重命名追溯依赖 Git 检测结果；缺少连续记录时注明，不能伪造身份连续性。
- 不含 blame、行级责任归属或语义历史分析。

### R-IMAGE：图片与特殊文件

- 首版图片格式基线为 PNG/JPEG/WebP，支持并排与滑动对比、尺寸显示、缩放/适应视图。
- 插入/删除图片只有一侧时正确表达；尺寸不同时保持原比例，不把强制拉伸误当像素差异。
- 图片损坏、无法解码、超过解码像素预算时显示类型及失败/降级状态。SVG 等主动内容不直接作为可信页面执行。
- 其他二进制只显示可得的大小/变化信息；不做 Hex/Office/PDF 专用比较。
- LFS 指针和子模块提交指针明确标识；不自动下载 LFS 内容或递归初始化子模块。

### R-REMOTE：显式获取远端状态

- 默认不联网；只有用户选择“获取远端状态”才执行 fetch，UI 说明会更新本地 Git 元数据，不修改工作区内容。
- 默认目标为当前分支上游所属 remote；没有有效上游时让用户选择已有 remote，不自行配置 remote/upstream。
- fetch 不 pull、不 push、不 checkout、不自动 prune、不递归更新子模块；不附带新的分支管理能力。
- 使用用户已有 Git 认证环境；失败/超时/取消明确结束。失败后保留已知快照但注明，不能宣称回滚所有已经写入的 Git 元数据。
- 本次 Oris 成功获取可记录完成时间；外部工具 fetch 的确切成功时间未知时显示未知。

### R-UX：通用使用体验

- 键盘可完成项目切换、文件选择、diff 导航与搜索；焦点可见，快捷键遵循平台习惯。
- 窗口大小、侧栏/日志展开、主题、字号保存在应用数据目录。
- 不运行远程网页或上传代码；图片和仓库文本均为不可信内容，只做阅读。

### R-PERF / R-SAFE / R-PLATFORM

- 性能要求与测量条件见 [验收计划](../validation/v1-acceptance.md)，不能用静态效果图作为证据。
- 浏览不改变工作区、index、refs 或仓库配置；fetch 是明确独立的元数据写入例外。
- 双平台分别验证实际系统 WebView、文件监听、Git 探测、中文路径和安装后启动。

## 3. 明确不支持

clone/init、stage/unstage、编辑保存、discard、commit/amend、checkout/switch、分支/标签/remote 修改、merge/rebase/cherry-pick、stash 操作、reset、push/pull；终端、PR/Issue、账号云协作、AI；blame、连续多文件 diff、AST/语义 diff、像素级分析、Hex/Office/PDF。

不构建自动重试、恢复作业系统或全仓内容索引。普通失败给清晰错误并停止；缓存和应用配置不得写入被浏览仓库。

## 4. 完成标准

所有需求组有实现与验收证据；五项任务均通过其验收；Win11 x64 与 macOS 14+ arm64 均有真实运行结果；未验证项明确列出且不得称 V1 已交付。性能预算必须在测试前固定，不能用降低标准解释已经发生的失败。
