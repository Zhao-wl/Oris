## 目标与最短路径

作为用户，我选择静态 PNG/JPEG/WebP 时能阅读真实旧新图片；遇到未合并文件时能查看 index stages 与当前工作区的版本差异，全程只读。

图片路径：选择本地范围 → 选图片 → 并排/滑动/缩放阅读 → 返回或切换文件。
冲突路径：选未合并文件 → 比较 stage 2→3 → 按需选择 Base/工作区 → 阅读或看到准确不可用原因 → 返回。

使用系统 Git；Win11 x64、macOS 14+ Apple Silicon 目标保持。复用现有文本阅读器及项目/文件导航，不扩大通用格式支持。

## 必要基础的边界

基础改动随对应闭环交付，不单独拆框架任务，也不引回上一版 A/D：

- 仅为图片和冲突表达逐侧存在/缺失、读取失败、解码失败、超预算及端点身份；空文件不是不存在，失败不能制造全量新增或伪零差异。
- 为所选静态图片识别签名/尺寸；为冲突获取 mode/OID/stage。仅做正确路由所需识别，不建立全格式分类器或统一二进制信息平台。
- 保留 repo/request/revision，外部变化后拒绝过期结果；按需读取当前两端，切换释放图片资源，不常驻四个完整版本。
- 冲突文本沿用现有编码与文本预算。不增加 UTF-16、旧式编码、完整 BOM/EOL 能力；现有解码失败提示保持准确。
- 未支持的二进制或对象在本轮入口显示可得的端点/OID/大小与不可显示原因即可；不增加 LFS pointer 解析、缓存查找、submodule 内部状态或 symlink 专用查看能力。
- 特殊 mode/非普通文件不得误走普通图像文件读取，不跟随链接、不初始化子模块、不自动拉取 LFS/缺失对象。必要的拒绝/降级不等于新增专用支持。
- 沿用 external diff/textconv/filter/fsmonitor 等既有只读边界；不执行仓库配置的外部命令。

## 闭环 A — 静态图片差异阅读

依赖：正式计划同步与后续实施授权；满足任务 02 原正式依赖门禁，并与当前 01/02 修复整合后核对接口。Windows 基础通过不替代 macOS 门禁。

用户故事：选择 PNG/JPEG/WebP 后，可以比较真实旧新图、透明区域和尺寸变化，通过缩放或滑动观察；新增/删除/坏图不会显示误导结果。

包含：

- 静态 PNG/JPEG/WebP，HEAD→Index、Index→Working Tree、HEAD→Working Tree 的真实内容。
- 并排与滑动；共用画布坐标和缩放倍率，保留原比例；适应视图、原始尺寸和字节数。
- 透明背景棋盘格及浅/深底；尺寸不同保持边界，滑动不能分别拉伸再叠加。
- 新增/未跟踪/删除存在侧单栏；仅一图时不显示无意义滑杆；一侧坏图/超预算时保留可用侧。
- 图片签名和尺寸预检；非支持格式、截断图、动画 APNG/WebP 清晰降级，不无提示自动播放。
- JPEG 方向策略明确并测试，存储尺寸与展示方向不混淆；不承诺专业色彩或像素级一致。
- 切文件/项目的过期结果拒绝、资源释放和可取消交互；保护现有单栏、轨道及项目标签行为。

排除：像素热图/相似度、GIF 预览、SVG 渲染、PSD/HDR/专业色彩比较、动画播放或逐帧 diff、图片编辑/导出保存、完整通用二进制查看器。

资源验收前固定：沿用研究第 6 节图片建议（每侧输入 ≤20 MiB、边长 ≤16,384、单图及双侧总像素 ≤40 MP；受控图片分配参考 ≤256 MiB）；这些是待测预算，不是已验证支持上限。需要修订时在执行前记录原因与采用值，不能测后放宽冒充通过。既有文本与整机性能目标不因此放宽。

验收：

- 研究 F01/F02 仅图片部分：三范围真实 blob/工作区内容正确，新增删除单栏、已有零字节坏图与缺失端点区分。
- F06/F07：透明、不同尺寸、方向、格式/签名不符、坏图/截断/动画降级，逐侧断言；完整并排/滑动/缩放，而非只验 PNG 能显示。
- F08 仅图片预算：字节/尺寸/总像素临界±1、有界读取/解码、失败后仍能切文件。
- F14 仅本入口只读回归，F15 仅图片/既有文本混合切换：仓库前后不变，标记程序未执行，30 次切换记录时延与内存释放。
- Win11 WebView2 与 Mac WKWebView 分别验证；未运行平台明确保留，不以 Chromium 或静态截图替代。GUI 验证遵守 AGENTS，不抢焦点、不操作其他应用窗口。

交付：图片选择→比较→退出闭环，R-IMAGE 图片部分及 A11 图片证据；历史提交入口由后移后的历史任务接入验证。

## 闭环 B — Git 冲突版本只读查看

依赖：A 通过；复用现有文本阅读器与 A 图片阅读器，不依赖新增编码或 LFS/submodule 支持。

用户故事：选择未合并文件后，能比较实际 stage 2/3，并回看 Base 或当前工作区；一侧删除、无法解码或二进制不支持时，也能明确知道各版本身份和存在性。

包含：

- 从真实 unmerged index 读取 mode/OID/stage，不靠工作区冲突标记判断。
- Base（stage 1）、stage 2（ours）、stage 3（theirs）、Working Tree 四个版本身份；默认 2→3，支持选择 Base→2/3、2/3→WT、Base→WT。
- 文本沿用当前支持范围；受支持静态图片用 A；其余仅端点/OID/可得大小及不可显示原因，不解析格式或对象。
- 缺 stage 明确显示缺失/删除侧与可读侧；已有空版本、读取失败与缺失分别表达。
- UU、AA、UD、DU、DD/AU/UA 的实际记录；复杂 rename/delete、rename/rename 逐路径呈现，不推断跨路径冲突图。
- 三种本地范围保留冲突专门说明，不把 unmerged 当普通已暂存内容；rebase 时固定 stage 编号，不武断标“我的/远端”。
- 外部解决/修改后的 revision 校验和刷新；WT 标为当前工作区，不叫“已合并结果”；同时最多按需读当前双端。
- 复用现有文本和 A 图片预算；缺对象/超限/不支持类型准确降级。

排除：编辑结果、Accept/Apply/解决/写 index、运行 merge/rebase、自动合并、冲突标记推断冲突、跨路径冲突组图、历史 merge 专用分析，以及任何完整编码/LFS/submodule/symlink 扩展。

验收：

- F09/F10：真实 stage OID/内容对照 Git；覆盖 modify/modify、add/add、双向 modify/delete、DD/AU/UA、二进制与图片冲突、rebase 和跨路径冲突。
- 缺 Base/2/3 不伪造空文件；删除冲突标记但 index 未解仍显示冲突；普通文本含标记不自动判冲突。
- Base/2/3/WT 选择能得到正确版本；单侧解码失败保留可用侧；跨侧计数不可计算时不能显示 0；非图片二进制只作本入口必要降级。
- 外部修改/解决后旧内容不能落屏；返回/切项目保持当前导航语义，版本读取量有界。
- F14 仅冲突入口安全回归、F15 仅文本/图片/冲突混合切换；全程工作区/index/refs/config 不变，不下载、不执行 driver/filter。
- 两平台分别给出运行证据；缺 Mac 不宣称最终通过。复杂状态若用底层受控 index 夹具补覆盖，须与真实 merge 生成证据分开。

交付：冲突选择→版本比較→退出闭环；“暂不支持冲突”提示不算通过。当前不支持的格式仍可降级，这不构成实现这些格式的额外任务。
