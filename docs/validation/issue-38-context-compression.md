# Issue 38：分层上下文与按需读取

2026-10-09，本地开发版本，产品验收待完成。本文覆盖前一版验证记录中的“400 项／70,000 字符”和一次装载附件方案。

## 实现边界

- 附件保存仓库、路径／OID、来源和版本引用。文件按目录、提交按日期建立索引；公共路径只在组名出现，网络请求使用本轮短编号。大目录进一步分组，所有条目保持可达，不默认截取前 400 项。
- 选择助手逐层导航元数据，再按需核对原文。用户选择文件／提交的边界保持不变，追加／移除／替换必须在各阶段一致。找到支持相关性的证据即可保留条目，这不是完整审查。
- 选择助手的正文核对达到累计预算时，保留余下的元数据初选并明确提示未核实；导航失败、读取失败、模式冲突、取消及版本变化不应用部分选择。
- 普通附件问答及解释使用受控的 `contextRead` 协议：展开已公开分组、打开附件片段索引、读取精确片段、继续后续差异。协议解释器不接受任意路径、shell 或 Git 操作。分组索引、片段及缓存均有当前请求内的编号映射。
- 读取正文前只发送目录；片段保留真实行号、左右版本和原文。网络投影省略本地路径 ID、请求对象、重复 diff 和内容哈希；完整来源仍留在本地用于验证与定位。
- 后端新增只读 `review_context_page`。分页游标覆盖所有差异上下文行，每页原文最多 6,000 字节，整行输出，下一页能读到文件后部。单行超过页容量、二进制或既有底层读取限制明确标为未覆盖，不伪造摘要。
- `@审查` 顺序遍历附件与续页，以有界证据片段审查；到累计预算时返回已覆盖／未覆盖统计。发现按来源校验后本地合并，不把所有原文重新送入一次大请求。
- 开始读取时重取当前来源身份；版本变化会说明采用新版本。读取期间再次变化则拒绝结果。不会因为删除“刷新文件”按钮而跳过校验。
- 索引、原文页及续读结果在一次读取循环内缓存；重复读取同一片段不重复读取正文，最终仍重新校验内容。跨用户轮次重新建立当前版本，不持久化模型语义摘要。

## 预算与可见限制

- 索引目标 2,000 tokens，精确证据窗口最多约 8,000 tokens；历史消息保留预算内完整的最近消息，不从消息中间截断。
- 使用 UTF-8 字节数作为保守 token 上界估算，不是提供方 tokenizer 的精确统计。AI 路由设置可调整单次上下文上限和单任务累计预算；默认 16,384／96,000，为输出额外预留空间。单任务最多 64 次模型调用。
- 单次上限须由用户设置为不超过真实模型容量；目前不自动探测各提供方模型容量。预算保存在本机，不随路由导出。
- 正文窗口滚动时旧证据可以退出窗口；模型的简短 notes 仅作为摘要，不作为原文引用依据。覆盖记录区分已展开附件、已知片段、实际提供片段和待续读入口。
- 完整审查当前采用逐片段推理，尚未提供全仓库依赖图或完整跨文件联合审查；结果明确标注该限制。没有引入 embeddings 或全量模型摘要。
- 选择助手仍要求无工具 API／Claude 连接；Codex CLI 的选择专用无工具通道仍未接入。解释及审查沿用其已有只读模型路由。
- 手动提交列表的 10,000 项批量保护、默认未推送提交首批 200 条的覆盖提示，以及旧显式 reviewRequest 的兼容读取能力仍保留。
