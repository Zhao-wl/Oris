# Oris 产品方向与首轮功能筛选

状态：历史提案，已由 [V1 产品规格](../specs/v1-product.md) 和 [已确认 UI/UX 基准](02-approved-ui.md) 替代。下文保留原始讨论记录，不能据此排除已纳入 V1 的任意版本比较、文件历史或图片 diff。

项目交互更新（2026-09-23）：用户取消本提案中的“固定项目”；现行规则为紧凑顶部标签、双击名称编辑别名、× 移除应用记录、独立拖动柄持久化顺序。历史固定/最近排序建议不再是实现或验收要求，详见上述现行规格。

## 已确认定位

高效、易读，让用户轻松感知文件变化。四项重点为多项目管理与快速切换、直观美观的 diff、高性能、清晰的提交记录与分支浏览。延续只读定位：不提供 checkout、暂存、提交、合并、stash、push 等操作。这里的分支管理指组织、浏览、筛选与比较，不改变工作区分支。

## 首轮筛选建议

| 方向 | 首轮重点 | 暂缓或不纳入 |
| --- | --- | --- |
| 多项目 | 最近/固定项目、名称与路径识别、项目快速搜索切换、每项目保留当前视图/文件/比较位置、当前项目变化数量 | 批量 Git 操作、项目内任务管理、所有仓库持续全量扫描 |
| Diff | 并排/统一、行内高亮、语法区分、上下文展开、差异跳转、文件路径搜索、树/列表、已暂存/未暂存区分、增删/重命名标识 | AST/语义 diff、Office/PDF 比较、可编辑 diff |
| 高性能 | 当前可见信息优先、切换时保留已读内容并标记刷新状态、取消过期读取、加载可感知、超大内容明确降级 | 无预算后台任务、为状态总览持续处理所有项目、未经实测的性能承诺 |
| 历史/分支 | 提交列表与紧凑拓扑、分支/标签/HEAD、提交详情和文件差异、作者/SHA/消息过滤、当前与浏览分支分离、上游及 ahead/behind | Git Flow、分支编辑、rebase、reflog 恢复、PR/Issue 工作流 |

图片 diff、连续多文件 diff、任意 refs 比较、文件历史/blame、跨会话已读标记列为下一层候选。二进制、图片、LFS、子模块和无法渲染的大文件仍应有准确状态，不能误报无变化。

## 信息架构与视觉提案

- 左侧为持久项目栏：固定项目、变化数、快速切换入口。项目切换不改变仓库内容。
- 顶部持续显示当前项目、实际工作分支、上游和基于本地快照的领先/落后。
- 主导航为“本地变更 / 提交记录 / 分支”。切换分支浏览只改变观察对象。
- 本地变更：文件导航 + 大面积 diff；工作区、暂存区、全部本地改动是比较范围，左右端点始终可见。
- 提交记录：紧凑拓扑和列表在上，提交详情、文件与 diff 在下。分支视图可进入对应历史，不要求 checkout。
- 中性底色、低饱和新增/删除背景、行内高亮加深；新增/删除同时用符号编码，不能只靠红绿。
- 多项目栏可收紧；内容区保持连续，避免装饰性卡片和信息仪表盘挤占 diff。

## 高性能如何验收（待确定目标预算）

分别测量首次打开、已打开项目切换、文件切换、历史筛选、滚动流畅度与空闲/峰值内存。结合项目数、文件数、提交数、单文件大小与巨大变更提交建立测试样本；分冷/热场景记录 P50/P95。先确定目标平台、典型仓库和压力仓库，再设明确预算。效果图中的瞬时切换是演示数据交互，不代表真实 Git 性能。

## 仍需产品决策

1. Windows 优先还是多平台同步：当前效果图采用桌面通用布局。
2. 是否允许 fetch 更新本地 Git 元数据：未确定前使用本地跟踪引用，不把 ahead/behind 声称为远端实时状态。
3. 多项目默认采用常驻名称列表还是紧凑图标栏：效果图提供设计选项。
4. 图片/连续多文件 diff 的首轮优先级，以及典型仓库和性能预算。
